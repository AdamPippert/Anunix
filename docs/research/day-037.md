# Day 037: Validate bounded changes to the workflow graph

The August 1 briefing treats collaboration topology as versioned execution state.
The comparison baseline, `01512bc`, executes workflow graphs and preserves paused graph structure through the Day 029 guards.
The baseline has no separate gate for a complete topology revision, revision budget, or rollback.

## Scope

The source is [Day 037 in the daily review](daily-review.md#day-037--2026-08-01).
The source message identifier is `8ee2a2ac-3033-40ce-9edf-df54b335bf33`.
The briefing recommends bounded structural repairs based on independent execution evidence.
This step adds deterministic validation and rollback for edge changes to an existing workflow.
The baseline test branch exposes unchecked replacement through an adapter over the existing edge storage.

## Implementation

The [topology controller](../../kernel/core/workflow/topology.c) validates the initial graph before enabling revision control.
Revision control defaults to disabled and accepts a lifetime limit from one through eight revisions.
Enabling control freezes the existing nodes and their interfaces.
Node replacement during resume also returns `ANX_EPERM` for a controlled workflow.

The controller accepts a complete replacement edge list and an expected revision number.
The graph permits at most 64 nodes, 128 edges, and eight ports per node.
Validation rejects absent nodes, invalid ports, incompatible port types, duplicate edges, self-links, and cycles before copying any edges.
The native wildcard port type remains compatible with every declared type.

A revision requires a completed run under the current revision and its sealed trace object.
The gate checks one successful entry per node and an execution order compatible with every current edge.
The [executor](../../kernel/core/workflow/workflow_exec.c) now seals the object before publishing the trace identifier or releasing its temporary entries.
Starting another run clears the previous trace reference and revision binding, so failed trace creation cannot reuse older evidence.
The executor also seals a completed resumed run.

Accepted revisions retain the previous edges and the evidence identifier.
They consume one revision from the lifetime budget and advance the revision number.
Rollback restores the previous edges, advances the revision number again, and does not refund the budget.
Either change clears the output table and requires another run before its results become current.

These operations require the trusted controller outside an active cell.
Running, suspended, and human-review states return `ANX_EBUSY` before any graph change.
A stale revision number returns `ANX_EBUSY`; an exhausted budget returns `ANX_EFULL`.
Missing evidence returns its object lookup error without consuming the revision budget.

The [native regression](../../kernel/core/tools/research_day037.c) rejects a cycle without changing the original graph or revision number.
It also checks absent nodes, invalid ports, duplicate edges, frozen editing APIs, and deleted evidence.
The fixture executes the original order, a revised order, and the restored order through the workflow executor.
It checks sealed traces, stale requests, budget retention after rollback, and both paused execution states.

## Limits

The controller validates structure and successful execution evidence; it does not diagnose task failures or prove improved task quality.
The change adds no agent, role, capability, or visibility grant.
The evidence requirement covers runs with one successful trace entry per node; traces with retry attempts require a separate acceptance policy.

The workflow registry and its returned native pointers retain their existing concurrency limits.
These checks do not isolate arbitrary kernel writes or provide atomic graph changes across concurrent processors.
Rollback restores graph structure without reversing effects from an earlier run.
The tests establish deterministic lifecycle behavior without a multi-agent performance claim.
