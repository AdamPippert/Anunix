# Day 020: Separate retention advice from memory protection

The July 15 briefing treats semantic retention metadata as advice for a memory controller.
The comparison baseline, `a7da2a2`, has logical memory tiers and decay scores.
The baseline lacks bounded retention hints and protection against tier removal.

Anunix's memory entries describe State Objects; the entries do not represent physical KV-cache regions.

## Scope

The source is [Day 020 in the daily review](daily-review.md#day-020--2026-07-15).
The source message identifier is `d2928218-8709-4a8b-8251-f76e37b0577c`.
This step adds bounded advice and controlled eviction to the existing memory tier records.

## Implementation

The [retention API](../../kernel/core/mem/retention.c) accepts priorities from zero through 100 points and lifetimes of up to 16 decay sweeps.
Both fields default to zero, which clears the hint.
A nonzero priority needs a nonzero lifetime.
The setter checks the object's metadata write permission and rejects malformed hints before changing the entry.
Hints affect eviction order without changing validation state, tier placement, or protection.

The controller selects a pool of up to 32 object identifiers for each eviction request.
The eviction API validates the whole pool before removing one L0, L1, or L3 placement.
Missing memory entries, duplicate identifiers, invalid counts, and unsupported tiers leave all placements and the output identifier unchanged.

The controller selects the highest score: capped decay minus ten times the active priority.
Object identifier order resolves score ties.
Every unprotected placement remains eligible, including the only candidate with maximum priority.
The per-entry decay step expires hints and clears their priority at the lifetime boundary.
The existing sweep applies that step to each memory entry.

The controller can separately protect currently occupied tiers.
Active cells cannot change that protection or invoke the eviction selector.
Demotion and forgetting return `ANX_EBUSY` for removal of a protected tier.
Operations that preserve every protected tier remain permitted.
Protected entries can still become stale; retention does not certify information quality.

The [native regression](../../kernel/core/tools/research_day020.c) checks advice, forced eviction, expiration, protected entries, malformed pools, and rejected caller requests.
The regression reads the protected object's sealed payload after eviction attempts and checks that the content remains unchanged.
The fixture advances only its own entries through decay and does not sweep unrelated live entries.

## Limits

Eviction removes a logical tier bit; eviction does not move or free physical RAM, GPU memory, or KV-cache blocks.
The underlying State Object and any admission charge remain until an explicit supported lifecycle operation releases them.
The controller determines the candidate pool; the selector does not discover the entire working set automatically.

Hint lifetime uses controller-invoked decay sweeps, without a wall-clock guarantee.
Callers can renew authorized hints, but renewed hints still cannot prevent forced eviction of an unprotected placement.
Trusted kernel code can still edit raw memory records.
The current APIs do not provide concurrent eviction transactions or reference-counted memory entries.

This step adds no prompt-region compiler, automatic semantic classifier, serving-engine adapter, or measured KV-cache improvement.
