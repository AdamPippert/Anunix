# Day 032: Bound child creation across the lifetime of a run

The July 27 briefing treats execution scope, expansion budgets, and termination conditions as runtime contracts.
The comparison baseline, `4c0bc25`, limits recursion depth and concurrent children but returns a child slot after destruction.
A run can repeatedly create and destroy children without exhausting those concurrent limits.

## Scope

The source is [Day 032 in the daily review](daily-review.md#day-032--2026-07-27).
The source message identifier is `52886424-fea8-48fb-adb3-5793d7b23eb6`.
This step adds a shared lifetime budget for child creation and an optional execution deadline.
The existing run fence carries both limits across descendants and separately bound roots.

## Implementation

The [run fence](../../kernel/core/cap/effect_fence.c) counts successful child creations through the [derivation path](../../kernel/core/exec/runtime.c).
Destroyed children do not refund that count.
The allocation gate checks the count before allocation and increments the count only after successful creation.
The gate holds the fence lock across both operations.
Invalid child types and failed allocations do not consume the budget.

The controller can set a finite limit from 1 through 1,024 child creations.
The default limit of zero preserves legacy behavior, but bound child creations still increment the count.
An explicit revision can expand the limit or reduce the limit to the current count.
A lower limit returns `ANX_EINVAL`; a stale control generation returns `ANX_EBUSY`.
Budget exhaustion returns `ANX_EFULL` without allocating another child.

The optional deadline uses absolute monotonic time in nanoseconds; zero means no deadline.
Fence checks and control reads detect expiry and permanently change the state to `ANX_FENCE_TIMED_OUT`.
That transition advances the effect epoch and blocks new children and protected effects.
The controller cannot renew an expired lease.
Already dispatched effects can still settle through the existing protocol.

An approval hold still permits computation within the child budget while blocking effects.
An active cell cannot revise the lease or derive a child through another cell as the parent.
Existing recursion, identity, inherited scope, and concurrent child limits remain part of admission.

The [native regression](../../kernel/core/tools/research_day032.c) exhausts a shared budget across a child and grandchild, then destroys both.
Another root on the same fence cannot create another child, and the registry count remains unchanged.
The fixture checks explicit expansion, stale revisions, invalid input, active caller restrictions, and permanent expiry.
The fixture also checks that expiry rejects a prepared effect while an earlier dispatched effect can settle.
The earlier Day 024 regression checks computation during an approval hold.

## Limits

The budget covers calls through child derivation, not arbitrary kernel allocation or direct creation of unrelated roots.
Trusted kernel code can still create an unbound run.
The change adds no token budget, model-call budget, progress certificate, static loop analysis, or automatic justification for expansion.

Expiry is checked at admission and control boundaries, without a timer interrupt or CPU preemption.
Work already admitted can continue computation after expiry.
The fence registry remains volatile and has no restart recovery.
The VM checks enforcement; the checks do not measure scheduler efficiency or prove bounded execution of arbitrary kernel code.
