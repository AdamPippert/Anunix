# Day 045: Verify predicted actions before publishing private results

The August 9 briefing treats speculation as preparation followed by deterministic verification of the chosen action and originating state.
The comparison baseline, `10fcbc7`, provides staged object mutation, resource leases, and governed external calls.
Those mechanisms do not provide a bounded private result tied to a predicted action and origin version.

## Scope

The source is [Day 045 in the daily review](daily-review.md#day-045--2026-08-09).
The source message identifier is `e5c38077-c49b-485a-9a11-b8747064f5a4`.
The briefing recommends cheap preparation, isolated speculative work, and commitment only after the actual action and origin match.
This step implements private candidate payloads for state-object replacement.
The baseline fixture demonstrates that eagerly dispatching a wrong prediction invokes its handler before the mismatch can be discarded.

## Implementation

The [speculation broker](../../kernel/core/state/speculation.c) copies a predicted action and candidate payload into a private record.
The record names an owner cell, originating object, and expiry deadline.
Preparation checks current read access and captures the origin's version, type, sensitivity, schema fields, and payload digest.
It rejects sealed or staged origins and does not stage, replace, or lock the origin for the preparation's lifetime.

Action descriptions contain one to 256 bytes.
Each origin and candidate payload has a one MiB limit.
The broker permits 64 records, two prepared candidates per owner, and 16 MiB of simultaneously reserved candidate bytes.
Deadlines can extend at most 30 seconds beyond preparation.

A prepared record retains its owner cell and prevents its destruction until the record closes.
Expiry checks release its private payload and owner reference.
Committed, discarded, and expired records retain their outcome until explicit release frees the record slot.
An owner can operate on its records; an active foreign cell cannot read, commit, discard, or release them.

Commit compares the actual action bytes and length with the prediction before touching the origin.
A mismatch discards the private result and returns `ANX_ECANCELED`.
A changed origin discards the result with `ANX_EBUSY`.
Neither path invokes an external handler or publishes candidate bytes.

A matching commit opens the origin and begins a stage attributed to the original owner.
It rechecks the origin and staging base after stage creation, then copies the candidate into the shadow payload.
The existing staged commit checks current write permission, owner lifetime, identity admission, and effect-fence state before publication.
Expiry or failed authority aborts the stage and discards the candidate.

Successful publication increments the origin version once and consumes the speculative record.
Repeating the commit cannot publish again.
The broker contains no external handler dispatch path; it supports state-object replacement only.
Aborted publication can append the existing staging-abort provenance event while leaving committed payload bytes unchanged.

The [native regression](../../kernel/core/tools/research_day045.c) discards a wrong action and checks the origin's version, payload, staging state, and provenance count.
The registered predicted-action handler remains uncalled.
The fixture also changes the origin, removes publication authority, holds the effect fence, and withdraws write access before commitment.
Each rejected candidate leaves the committed payload intact.

The fixture enforces the two-candidate owner limit and invokes a foreign cell that attempts to operate on another owner's record.
A matching authorized commit publishes the private bytes once.
A short deadline then exercises expiration, and explicit cleanup returns all record slots and owner references.

## Limits

The caller supplies the candidate payload and the authoritative action description.
Matching action and origin prove those declared identities, not the correctness of the candidate computation.
The broker does not execute tools in filesystem forks, generate predictions, prewarm VMs, or validate external service effects.

The reserved-byte ceiling covers candidate payload copies.
It excludes record metadata, source payloads, and the temporary copies used by the existing staging implementation.
Recorded expiry releases broker resources when the broker is next called; it is not a hardware preemption timer.

The origin checks and staged publication use the existing object-store locking and version rules.
They do not establish a transaction across several objects or serialize arbitrary trusted-kernel writes outside those rules.
The outcome catalog lasts for the current kernel lifetime.
The tests establish discard and publication behavior without a critical-path latency or speculative-hit-rate claim.
