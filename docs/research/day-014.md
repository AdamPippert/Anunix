# Day 014: Retain named intent with observed effects

The July 9 briefing connects agent intent, caller identity, policy decisions, and observed effects through one execution record.
Anunix already retains caller identifiers, parent lineage, admission denials, and transport accounting.
The comparison baseline, `57873d0`, starts each runtime trace with a generic description.
After the cell is destroyed, that record cannot identify the original intent name.

## Scope

The source is [Day 014 in the daily review](daily-review.md#day-014--2026-07-09).
The source message identifier is `d2eef052-ef2c-4ac2-9fd2-5230b7b5aa2e`.
This step connects the existing causal identifiers to a retained intent name.

## Implementation

The runtime copies the cell's intent name into the trace's creation event before admission or dispatch.
Cancellation before execution also records the intent name.
The copy is bounded by the intent field and retains at most 127 name bytes plus the string terminator.
Later changes to the cell cannot change the copied name.

The [native regression](../../kernel/core/tools/research_day014.c) exercises denied, allowed, and cancelled external calls.
Each trace retains its own name, cell identifier, object creator, and terminal outcome after cell destruction.
The handler records the active caller identifier and changes the live name after dispatch.
The allowed call's stored trace retains the earlier name and its observed response accounting.
The denied and cancelled cases do not invoke the handler or record a committed effect.

## Limits

The intent name is descriptive caller-supplied metadata, not verified evidence of the caller's motives.
This change does not record full prompts, request bodies, endpoint addresses, or subprocess activity.
Transport results remain handler-reported observations rather than proof of an external system's final state.
The trace remains local to the current object store and does not establish reboot persistence or signed evidence.
