# Day 075: Check memory compatibility before reusing projections

The September 8 briefing treats execution, memory, coordination, and quality as explicit compatibility contracts.
At comparison baseline `d495c83`, Anunix manages memory placement but does not bind retrieval projections to a declared reader and embedding space.
This step adds a private memory contract and a bounded index with exact compatibility checks.
Changing the reader or embedding space blocks incompatible reuse even when vector dimensions remain equal.

## Scope

The source is [Day 075 in the daily review](daily-review.md#day-075--2026-09-08).
The source message identifier is `1596f5f2-799b-44ea-9b3e-36b9d0f0c6ee`.
The briefing describes substrate disclosure, memory portability, team coordination costs, and quality propagation through workflows.
The native experiment implements the memory compatibility boundary.
It does not reproduce model-upgrade accuracy, team coordination measurements, or quality prediction.

The briefing distinguishes a vector's binary dimensions from its embedding-space identity.
It also separates canonical evidence from a replaceable memory projection.
The experiment applies both distinctions with deterministic toy projections.
Those projections are not learned semantic embeddings.

## Comparison

The memory plane tracks placement, validation, retention, and admission ownership.
ICM annotations describe artifacts without granting authority.
Day 073 adds role and scope ceilings for assembled context.
None of these APIs checks a retrieval index against the owner's current reader and embedding contract.

The [memory ABI types](../../kernel/include/anx/memory_abi.h) identify reader descriptors, embedding descriptors, indices, and query results.
The [implementation](../../kernel/core/mem/memory_abi.c) maintains the current contract separately from captured index bindings.
A controller can replace the current contract without modifying the canonical source objects.
Query admission compares exact captured bindings before using the stored vectors.

## Implementation

The controller assigns one current contract to each owner.
The registry supports at most 16 contracts and 16 indices.
Each contract retains its owner, ancestry, identity record, reader descriptor, and embedding descriptor.
Descriptor snapshots include the object identifier, version, payload length, sensitivity, and actual content digest.
Contract replacement needs the current epoch and issues a new epoch.

Reader descriptors use the fixed `anx:memory/toy-reader/v1` schema.
Embedding descriptors use `anx:memory/toy-space/v1`.
The implementation supports semantic schema version one and four vector dimensions.
Two embedding transforms select different coordinate orders from a source digest.
Unsupported descriptor formats reject replacement without changing the active contract.

The controller builds an index from one to eight distinct canonical byte objects.
Each object must be sealed and contain between one and 1024 payload bytes.
The index captures the current contract and each canonical object's identity and content digest.
It stores the resulting four-byte vectors separately from those sources.
The controller can build another index from the same canonical objects under a replacement contract.

Query admission checks the current owner, scope, identity, reader, and embedding descriptor.
The index's captured descriptors must match the current contract by identifier, version, size, sensitivity, and digest.
Owner identity and ancestry must also match their captured bindings.
Equal dimensions alone cannot satisfy these checks.

A query reads a sealed canonical byte object and constructs its vector under the current contract.
The runtime rechecks every indexed canonical source before comparing stored vectors.
It selects the smallest squared distance, resolving equal distances by source order.
The result identifies the source object, index, current contract epoch, and distance.
Failed queries preserve the entire caller output.

The owner or controller can inspect the current contract and query its indices.
Only the controller can replace contracts or create and remove indices.
Indices retain their contract until cleanup; removing a referenced contract returns `ANX_EBUSY`.
Returning to exactly matching descriptor bindings permits reuse of an older compatible index despite a newer contract epoch.

## Native checks

The [regression](../../kernel/core/tools/research_day075.c) builds an index from `alpha` and `beta` under the first reader and embedding space.
A separate query object containing `alpha` returns the canonical `alpha` object with zero distance.
Both available embedding spaces have four dimensions.

| Contract change | Existing projection | Query result |
| --- | --- | --- |
| No change | Matching reader and embedding space | Exact match |
| Replace embedding space | Old embedding space | Rejected |
| Rebuild from canonical sources | New embedding space | Exact match |
| Replace reader with an equally shaped descriptor | Old reader binding | Rejected |
| Rebuild under the new reader | Matching replacement contract | Exact match |
| Restore the original descriptor bindings | Original index | Exact match |

Changing a copied index descriptor cannot relabel the private projection.
An unsupported semantic schema and a stale contract epoch cannot replace the current contract.
Duplicate canonical identifiers reject index construction.

Corrupting a canonical source blocks the whole query, including corruption of a source that would not be the nearest match.
Changing a source version, corrupting the embedding descriptor, or revoking source access also blocks reuse.
The fixture restores each injected fault before continuing.
Foreign queries and active-Cell attempts to change the contract or index are rejected.
The active owner completes a query using the restored compatible contract.

## Limits

The reader is a typed compatibility descriptor, not an executing language model.
The embedding transform uses content digests, not semantic inference or trained weights.
The exact-match fixture proves contract enforcement and rebuild mechanics; it does not measure retrieval quality after a real model upgrade.

The controller must assign the correct reader and embedding descriptors.
This API does not automatically observe changes in every existing model backend.
Other memory and model APIs retain their existing behavior.
The fixed schema supplies declared compatibility, not a learned proof that two different readers behave equivalently.

Indices retain source identifiers and verify source bytes at query time.
They do not prevent explicit deletion of canonical objects; a missing source causes query failure.
The implementation provides no disk recovery, persistent migration journal, incremental mixed-space index, or cross-owner sharing.
All contracts and projections remain within the current boot.
