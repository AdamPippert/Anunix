# Day 012: Observable admission gates

The July 7 briefing places lifecycle, resources, and audited authority behind a typed runtime boundary.
Anunix already records execution events and seals traces.
The comparison baseline, `c20f683`, records generic admission failures and permits an external call when trace writing is disabled.
It also waits until after execution to allocate the materialized audit object.

## Scope

The source is [Day 012 in the daily review](daily-review.md#day-012--2026-07-07).
The source message identifier is `afc05449-e490-4a36-8b73-13994999e7b0`.
This step makes external admission denials explicit and reserves their audit storage before dispatch.

## Implementation

The trace identifies the denied gate: delegated scope, missing descriptor, authority, required audit, or audit storage.
A typed denial event records the error and a short explanation.
An external call with trace writing disabled is denied and still receives a denial record.

The runtime reserves a full trace object before invoking an external handler.
Reservation failure prevents dispatch.
Finalization updates the reserved payload and seals it; the cell retains the object's identifier.
The trace schema advances to `anx:schema/cell-trace/v2` for the added fields.

If finalization fails after execution, the runtime returns `ANX_EAUDIT` and preserves the completed state.
The error describes recording failure and must not be interpreted as an undone effect.
The prepared record remains addressable, but an unsealed record is incomplete.
The same cell cannot run again.

The [native regression](../../kernel/core/tools/research_day012.c) checks four admission denials and their sealed records.
It verifies that none invokes the handler or records a committed external action.
The authorized handler verifies that its prepared audit object already exists.
A separate case injects finalization failure after the handler completes and checks the distinct audit error.

## Limits

The fault cases simulate reservation and finalization errors through hooks compiled only into research and host test builds.
They do not simulate a power failure or reproduce physical memory exhaustion.
The record lives in the current object store; this change does not establish persistence across guest reboot or provide signatures.
Unsealed prepared records cannot be treated as complete evidence of what ran.
If storage cannot record a denial at all, the runtime returns the original error without invoking the handler.

Trusted kernel code still has direct access to trace and object structures.
The prepared record is not a transaction with an external system.
A handler's transport failure remains separate from audit finalization failure.
