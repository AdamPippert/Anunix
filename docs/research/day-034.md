# Day 034: Keep preparation separate from publication authority

The July 29 briefing permits speculative preparation while withholding authority for committed state changes and external effects.
The comparison baseline, `673125e`, stages payload writes but publishes them without checking the staging cell or its run fence.
A read handle or a different cell can also resolve another stage.

## Scope

The source is [Day 034 in the daily review](daily-review.md#day-034--2026-07-29).
The source message identifier is `0b7c44cc-1651-400d-828e-5eab296603de`.
This step applies the preparation boundary to native staged objects.
The existing effect protocol provides the external-effect gate.
The step does not add a sandbox predictor or nested virtual machine manager.

## Implementation

The [staging path](../../kernel/core/state/stage.c) checks a writable handle and current object write permission before creating a shadow copy.
An active cell must name itself as the staging actor.
The [payload write paths](../../kernel/core/state/objstore.c) reject a different active cell before changing the shadow copy.
Readers continue to see the committed payload until publication.

Publication checks the recorded actor and the current object write policy.
A nonempty actor identifier must still resolve to a cell with side-effect permission, a nonterminal state, an admitted identity, and an open run fence.
A read handle cannot publish or abort a stage.
The original object version must still match the stage version.
The object lock protects the checks against its version and the payload replacement.

| Condition | Publication result | Stage result |
| --- | --- | --- |
| Missing effect permission | `ANX_EPERM` | Retained for explicit resolution |
| Approval hold | `ANX_EBUSY` | Retained for explicit resolution |
| Closed run fence | Existing fence denial | Retained for explicit resolution |
| Different active actor | `ANX_EPERM` | Unchanged |
| Missing recorded actor | `ANX_ENOENT` | Retained for cleanup |
| Changed base version | `ANX_EBUSY` | Retained for explicit resolution |
| Exhausted object version | `ANX_EFULL` | Unchanged |

The owning cell can abort its private work after effect permission is withdrawn or the run enters an approval hold.
Trusted control can abort an abandoned stage through a writable handle.
Abort preserves the committed payload, version, and content hash, while the existing provenance log records the attempt.
Trusted stages with an empty actor identifier retain the control path and still check object write permission.

The [native regression](../../kernel/core/tools/research_day034.c) stages a changed payload, withdraws effect permission, and attempts publication and effect preparation.
Both attempts fail, and abort preserves the original payload, version, and hash.
Another case places the active run on hold and rejects publication, effect preparation, and nested external invocation.
The fixture checks foreign writes, foreign resolution, read handles, changed write policy, and an injected version advance.
A fresh stage under an authorized actor publishes successfully.

## Limits

The stage contains one shadow payload per object; the change adds no transaction spanning several objects or external-effect buffer.
The recorded actor has no automatic authority transfer after completion or destruction.
The fixture injects a version advance to test rejection; it does not establish concurrent writer behavior.

The change applies to the staged publication path and its shadow writes.
It does not add an effect gate to every direct payload write, allocator, VM operation, or arbitrary kernel mutation.
The object lock does not make identity revocation and fence changes atomic with every publication step.
The tests establish sequential enforcement, without formal model checking or a sandbox escape proof.
No speculative startup latency, prediction quality, or memory-pressure benefit was measured.
