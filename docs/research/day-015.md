# Day 015: Preserve eligible session affinity

The July 10 briefing treats a session as a placement unit with continuity across individual inference requests.
It also separates planning from faster execution and control paths.
Anunix's comparison baseline, `09a3718`, scores routes independently and exposes no session affinity record.

## Scope

The source is [Day 015 in the daily review](daily-review.md#day-015--2026-07-10).
The source message identifier is `5437e7e4-38ad-4556-98c7-08606daa9991`.
This step adds an optional kernel API for session placement within a declared model backend pool.
The regression baseline includes an API stub; its failure records the missing session placement behavior.

## Implementation

The caller owns a routing record with at most eight unique engine identifiers, required capabilities, the selected engine, and a placement count.
The first placement uses Anunix's existing engine score.
Later placements retain the selected engine while it remains eligible, even when another backend's score rises.
The planner scores the remaining eligible pool members after the previous engine becomes ineligible.

Each placement checks current availability, model engine class, capabilities, locality, network permission, and remote-model permission.
Only available or degraded engines qualify.
Malformed records and exhausted placement counters fail before mutation.
A pool without eligible backends causes rejection and preserves both the previous routing record and result.

The [native regression](../../kernel/core/tools/research_day015.c) exercises two registered backends.
It checks retained affinity, seven unavailable lifecycle states, missing capabilities, network denial, and locality changes.
The fixture also checks malformed records, counter exhaustion, remote-model denial, and fallback after backend removal.
The regression releases its engines after each invocation.

## Limits

This API is optional; the existing per-cell planner does not automatically use a session record.
The caller must declare backends that serve the same logical model workload.
The record is a placement hint and grants no execution or data-access authority.
Its counter measures accepted placements, not completed inference turns.

This change does not reserve KV state, hold engine leases, migrate model state, or measure throughput improvements.
Initial placement uses existing scores rather than session load balancing.
The implementation assumes the current synchronous kernel execution model and does not add concurrent registry lifetime protection.
