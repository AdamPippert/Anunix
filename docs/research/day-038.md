# Day 038: Stop reusable workflows when their assumptions change

The August 2 briefing proposes progressive compilation from exploratory agents into hybrid workflows and deterministic programs.
The comparison baseline, `533e417`, validates workflow templates and supports bounded topology revisions.
The baseline does not bind a reusable execution form to current object versions or demote that form after drift.

## Implementation

The [reuse guard](../../kernel/core/workflow/reuse.c) defaults to absent, so existing workflows retain their behavior.
A trusted controller can bind a hybrid or deterministic form outside active, suspended, and human-review execution.
Binding validates the graph through the existing template validator and records its native graph and policy digest.
The gate rejects placeholder operations and unbound agent or subworkflow delegation.

The deterministic form permits triggers, read-only state references, fan-out, fan-in, and output nodes.
The hybrid form also permits implemented model, cell, retrieval, review, and capability-promotion nodes under their existing authority checks.
These forms classify the declared operations; neither form grants access or effect authority.

A binding accepts at most eight distinct object preconditions.
Each referenced state object must appear in that list.
The guard records each object's identifier, version, type, sensitivity, and payload digest.
Each object has a one MiB payload limit for this check.
An unresolved staged mutation returns `ANX_EBUSY` during capture.

Before a run or resumed dispatch, the executor compares the current graph and object conditions with the binding.
The object check reevaluates current read access and hashes the current payload under its object lock.
Drift returns `ANX_EBUSY` before execution; deletion and access withdrawal return their object errors.
A denied run clears old outputs and trace references without advancing the previous start time.

The guard demotes a failed form to exploratory and records the rejection reason.
Demotion remains in effect after an object or permission returns to its previous state.
The controller must bind a newly validated form before another reusable run.
A workflow failure also demotes the form.
The caller can abort a suspended continuation after demotion.
The status view counts completed runs since the current binding.

The [native regression](../../kernel/core/tools/research_day038.c) runs a deterministic state-to-output graph and checks its actual output identifier.
It changes a precondition payload and checks rejection before another node executes.
The fixture checks duplicate and missing declarations, graph drift, model-node rejection, revoked read access, sticky demotion, and deleted conditions.
A denied hybrid promotion node exercises failure demotion and blocks retry while allowing abort.

## Limits

Binding establishes structural validity and pins declared assumptions; it does not certify task correctness or infer missing semantic preconditions.
The controller supplies the object list and decides when another binding has adequate evidence.
The change adds no automatic trace mining, model-generated compiler, successful-run promotion threshold, or learned recognition classifier.

Demotion returns control to the caller; the kernel does not automatically launch an exploratory agent.
The state-reference fixture passes object identifiers through the existing executor without a model invocation or external effect.
The tests establish reuse rejection and lifecycle behavior without a latency, cost, or task-success claim.

The digest uses native in-memory graph structures and is not a portable artifact format.
Checks occur at run and resume entry, without holding all dependency locks throughout execution.
The change does not provide a cross-object snapshot or protect against concurrent mutation after those checks.
Existing workflow registry pointers remain accessible to kernel code.
