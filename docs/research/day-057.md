# Day 057: Gate investigation on calibrated regime exits

The August 21 briefing reserves expensive policy search for departures from known operating conditions.
It separates deterministic regime detection from evidence that justifies a replacement policy.
At comparison baseline `5d84358`, Anunix compares two adaptive averages without retaining the policy's calibrated range.
A sustained change eventually makes those averages converge, even outside the original operating conditions.

## Scope

The source is [Day 057 in the daily review](daily-review.md#day-057--2026-08-21).
The source message identifier is `e83e8807-e735-4161-b007-45ecbc8e3ed1`.
This step adds an explicit range and one investigation event per departure.
The controller supplies the calibration; the detector does not certify a measured policy advantage.

## Implementation

The [regime detector](../../kernel/core/regime/regime.c) retains a private range for the current routing generation.
The controller can bind an inclusive minimum and maximum through the [regime API](../../kernel/include/anx/regime.h).
An invalid range returns `ANX_EINVAL`.
A stale generation or an active routing trial returns `ANX_EBUSY`.
Rejected bindings preserve the detector and the caller's output.

The detector suppresses decisions during its first 32 samples.
Its status exposes that warmup separately from the legacy stable state.
After warmup, an out-of-range sample raises an event and marks the regime escalated.
Adaptive averages cannot declare that departure stable.
Three consecutive in-range samples return the detector to stable; another departure resets that count.

The controller can claim each event once.
The claim checks the current policy generation and rejects active routing trials.
Continued out-of-range observations produce no further events until the detector returns to the calibrated range.
Bindings and events use identifiers that remain unique across resets during the boot.

An event records the first departure sample, bounds, binding, and policy generation.
The event grants no permission to install a policy.
The existing [tuning gate](../../kernel/core/route/tuning.c) still checks a candidate and can restore the incumbent after rejection.
A rejected trial changes the generation, so a controller must explicitly bind the restored weights to a new calibration context.

Only trusted controller code can observe telemetry, bind a range, or claim an event.
Calls from an active Cell return `ANX_EPERM`; reset and initialization calls from that Cell leave state unchanged.
Read access returns a copy of the detector status.
The implementation uses checked unsigned distances for both averages, including samples at the signed 64-bit limits.

## Native checks

The [regression](../../kernel/core/tools/research_day057.c) models a latency metric with a calibrated range of 850–1150 nanoseconds.
It first feeds 200 samples at 1000 nanoseconds, then 220 samples at 5000 nanoseconds.
The baseline returns to stable after the averages converge.
The candidate retains the calibrated departure and publishes one investigation event.
A further 200 departure samples cannot claim a second event.

The fixture rejects a candidate with an invalid cost divisor before a trial starts.
A separate valid trial changes one weight, then restores the original weights after explicit rejection.
The fixture checks boundary returns, interrupted return sequences, stale policy events, and a fresh binding after rejection.

Other checks cover warmup, caller mutation of the supplied range, invalid bounds, and an active Cell's denied mutations.
The fixture also feeds the minimum and maximum signed 64-bit values through both averages.
Failed event claims preserve the caller's output.
Cleanup removes the fixture's binding and preserves the incumbent weights.

## Limits

The calibrated range describes one caller-defined metric, with consistent units supplied by that caller.
The controller's calibration claim is not a benchmark receipt or a policy proof.
An unbound detector retains its original advisory behavior and cannot issue investigation events.
The bound detector uses raw samples and a fixed return count; it does not estimate statistical confidence or an optimal detection threshold.

The event API is available for controller polling; no service automatically invokes an AI model.
The manual tuning path remains available independently of these events.
Event generation limits repeated investigation signals, but it does not enforce a model budget or an event's later use.
A copied event can become stale immediately, so existing candidate gates must recheck the generation before any live policy change.

This fixture does not compare real workload latency, model cost, false alarms, or continuous versus occasional AI control.
It does not reproduce the briefing's scheduling, cache-affinity, profiling, readiness, or accelerator performance results.
