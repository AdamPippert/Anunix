# Day 042: Release phase leases before changing resource needs

The August 6 briefing recommends exposing agent roles and phase transitions to the resource controller.
The comparison baseline, `2d349b5`, supports engine leases and bounded child reservations.
The baseline does not associate those leases with successive phases of one cell.

## Scope

The source is [Day 042 in the daily review](daily-review.md#day-042--2026-08-06).
The source message identifier is `401f482f-a77c-4c64-949e-0fe1fd3af2b7`.
The briefing separates control, orchestration, and runner roles, with different resource needs during tool, inference, review, and wait phases.
This step adds deterministic phase admission to the native lease ledger.
The baseline regression grants two independent leases and exposes the missing shared phase boundary.

## Implementation

The [phase broker](../../kernel/core/route/phase.c) accepts controller-issued contracts for up to 128 cells.
A contract declares a role and enabled phases with memory tier, memory ceiling, accelerator type, and accelerator percentage ceiling.
The broker copies the contract into private storage and rejects later attachment attempts for the same owner.
Changing the caller's original contract cannot expand the installed limits.

Control cells can enter orchestration and wait phases.
Orchestrator cells can also enter review.
Runner cells can enter tool, inference, review, and wait phases.
Only runner contracts can reserve accelerator capacity through the broker.
These role checks limit phase admission without granting task, tool, or control-plane authority.

An owner cell or the controller can request a phase within its contract.
The broker reserves the requested resources through the existing global lease ledger and records the lease identifier in its phase view.
Each attached cell has at most one active phase lease.
Starting another phase returns `ANX_EBUSY` until the current phase finishes.
Global capacity checks and the contract's ceilings can reject requests without changing the current view.

Finishing first releases the current lease, then marks the cell idle.
Recorded memory use or remaining child leases make release return `ANX_EBUSY` and preserve the active phase.
A later phase receives a fresh lease with its own resource type and reservation.
A global monotonic epoch rejects stale requests, including requests issued before detachment and reattachment.
Epoch exhaustion prevents new admission while allowing existing leases to close.

The broker retains a reference to each attached cell.
Cell destruction remains blocked until the controller finishes its phase and detaches the contract.
Terminal cells cannot begin another phase, but the controller can still close their leases.
An active cell cannot attach, detach, or change its contract, and cannot operate on another owner's phase.

The [native regression](../../kernel/core/tools/research_day042.c) starts a 2,048-byte tool phase in memory tier L1.
It rejects a concurrent 4,096-byte inference phase in L0 with a ten-percent GPU reservation.
The test confirms that rejection preserves the original lease and leaves L0 and GPU availability unchanged.
It then checks busy memory, child leases, stale epochs, disabled phases, and requests exceeding the copied contract.

After releasing the tool lease, the fixture starts inference and checks the new reservation and restored L1 capacity.
An actual owner cell begins and finishes a wait phase, while a foreign cell receives `ANX_EPERM`.
The fixture checks cell lifetime, terminal-state rejection, and complete reservation recovery after both phases finish.

## Limits

The change enforces native ledger reservations and phase transitions.
The ledger still uses its existing default capacities; a reservation does not configure CPU affinity or allocate physical GPU memory.
The tests exercise reservation accounting without measuring tool latency, CPU utilization, cache locality, or accelerator throughput.

The controller and participating drivers must establish physical quiescence and update the lease's recorded usage before finishing a phase.
A zero usage counter does not prove that an external device has stopped.
The broker does not preempt hardware work, assign CPU pools, consolidate models, or provide Linux scheduling interfaces.

The private broker owns its phase leases through closure.
Trusted kernel code must not free or replace those leases through the legacy raw lease API.
Existing raw-pointer and registry concurrency limitations remain outside the phase broker's serialization.
Contracts and phase state last for the current kernel lifetime; durable campaign recovery requires a separate state format.
