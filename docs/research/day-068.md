# Day 068: Suspend a continuation without discarding useful progress

The September 1 briefing distinguishes short waits, long suspensions, and discarded acceleration state.
It separates useful semantic progress from physical state that a runtime can reconstruct.
At comparison baseline `aa6714c`, Anunix can park a phase lease and retain results across worker replacement.
This step coordinates those mechanisms through a bounded suspension contract.

## Scope

The source is [Day 068 in the daily review](daily-review.md#day-068--2026-09-01).
The source message identifier is `77557664-206e-4b62-b50b-b5960f80d9ce`.
The briefing discusses KV retention, semantic recovery, safe policy selection, and object-based interfaces.
Its proposed suspension contract motivates this implementation.
The experiment does not reproduce its throughput measurements or implement learned retention economics.

## Comparison

Day 052 parks a quiescent phase and releases its reserved memory and accelerator share.
Day 060 moves immutable resource views between physical pools.
Day 067 retains a continuation's owner, worker bindings, and recorded results.
Those mechanisms previously had no shared distinction between short waits, long waits, and discarded model materializations.

The [continuation implementation](../../kernel/core/workflow/continuation.c) now binds one existing phase and one sealed toy-model source to its suspension contract.
The private materialization uses a dedicated resource pool with one physical page.
A separate semantic checkpoint identifies the latest recorded completion.
Wait transitions and cache replacement preserve that checkpoint.

## Implementation

Configuration requires the current continuation epoch, current phase epoch, an active phase, and a valid sealed toy-model image.
Only one configured continuation can use an owner's phase reservation.
The registry captures the model's identifier, version, size, sensitivity, and actual digest.
The existing owner policy and identity commitment remain authoritative.
The controller cannot change the contract through a copied public view.

| Continuation state | Phase reservation | Physical model page | Capability dispatch |
| --- | --- | --- | --- |
| Runnable | Held | Present | Allowed after current checks |
| Short wait | Held | Present | Blocked |
| Suspended | Released | Present | Blocked |
| Hibernated | Released | Absent | Blocked |

A tool-wait reason selects a short wait.
A human-approval reason selects a long suspension or upgrades an existing short wait.
Long suspension uses the existing phase-parking API and therefore requires a quiescent lease.
It releases reserved capacity while retaining the model page.
An explicit hibernation step releases the private view and destroys its pool, which frees the physical page.

The sealed model source and completed results survive that physical reclamation.
The registry keeps its semantic checkpoint, completed operation keys, worker bindings, and logical owner.
It does not release or reinterpret an uncertain external operation.
An uncertain record cannot enter this suspension contract.

Resume checks the owner's current scope, identity, contract, effect fence, and scheduler domain.
The captured policy must still match.
The phase must still match its recorded epoch, lease state, role, and resource dimensions.
The transcript, completed result objects, original request sources, and model source must pass their current integrity and access checks.

A short wait resumes with the existing lease and cache generation.
A suspended continuation verifies its retained materialization before reacquiring the saved phase request.
A hibernated continuation checks available capacity before reconstructing its materialization from the sealed source.
The phase API then checks capacity again during reservation.
Successful reconstruction advances the cache generation and receives a fresh phase lease.
An old generation cannot read the replacement cache.

Predictable capacity failures leave the continuation hibernated without allocating a cache or transcript event.
A later failure discards any temporary materialization.
It preserves the checkpoint, phase state, public epoch, and caller output.
Invalid model or semantic evidence fails before phase reacquisition.
The controller must resolve the failed condition before another resume attempt.

Each resource transition prepares its sealed event before changing the phase or discarding retained resources.
The registry publishes that event only after the resource operation succeeds.
A failed transition removes the prepared event and preserves the existing transcript.
This ordering avoids a failed event allocation after a successful phase transition.

The model-read API permits only the owner or controller in the runnable state.
It checks the continuation epoch, cache generation, current source, phase, and actual cached bytes.
Private pool and view handles are not exposed by this API.
Existing object reads still enforce the logical owner's current access and record active sensitivity observations.

## Native checks

The [regression](../../kernel/core/tools/research_day068.c) first records an actual provider result and configures a toy-model materialization.
The materialized image must produce `AAAA` through the verified CPU generation path.
A short wait must retain the phase reservation and page while blocking another capability call.
Resuming that short wait must preserve the lease and cache generation.

An active byte in the phase lease must prevent long suspension.
A quiescent long suspension must restore 4096 bytes of ledger capacity and 25 percentage points of accelerator capacity.
It must retain the materialized page and the recorded result.
A corrupted retained cache must fail resume.

Hibernation must free one physical page while keeping the sealed result readable.
The fixture then changes model versions, model bytes, access rules, a request-source version, and completed-result bytes.
Every invalid resume must preserve the hibernated state and caller output.
A held effect fence and a changed owner policy must also block resume.

Competing leases separately exhaust memory and accelerator capacity.
Each capacity rejection must preserve the parked phase without allocating temporary state.
A research-only fault after reconstruction must release the temporary page and preserve the parked phase.
After capacity returns, reconstruction must advance the cache generation and create a new phase lease.
The restored image must produce the same `AAAA` output.

A later capability call must add one new completion after resume.
A foreign active Cell must not read the model materialization.
An active owner must read its recorded result and execute the restored image.
Active Cells cannot configure or change the suspension state.

## Limits

The physical state in this experiment is a 72-byte toy-model image stored in one 4096-byte resource page.
The cache statistics measure the dedicated pool's pages and live bytes.
Sealed transition events allocate separate object-store metadata, so hibernation need not increase the kernel's net free-page count.
The accelerator share is an existing admission-ledger reservation; the experiment does not allocate GPU HBM or KV state.
Its CPU execution verifies reconstructed bytes and output, not GPU restoration performance.

The initial candidate failed a global free-page assertion during a rejected resume.
Its [VM report](evidence/day-068/initial-candidate.json) and [serial log](evidence/day-068/initial-candidate-serial.log) preserve that result.
The continuation and phase remained unchanged, but the prepared transcript event consumed metadata pages.
The corrected implementation checks predictable failures before allocation and measures cache reclamation separately.
The existing object store retains allocations for deleted metadata objects; this step does not add garbage collection.

The contract gates this continuation's dispatch and model-read APIs.
It does not suspend arbitrary native threads, sandboxes, network sessions, or every direct operation available to the owner.
The resource policy uses explicit controller decisions rather than timers, approval predictions, or an opportunity-cost model.
A human-approval wait records a reason; resume does not grant more authority.

The semantic checkpoint and sealed source remain in the current object store.
Hibernation describes physical reclamation during one boot and does not imply recovery after power loss.
The workflow checkpoint API remains separate.
Controller cleanup removes the continuation's private materialization; the existing phase attachment requires its own cleanup.
