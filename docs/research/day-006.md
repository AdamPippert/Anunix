# Day 006: Child tool scopes

The July 1 briefing treats a tool invocation as a child resource scope within an agent lifecycle.
The runtime owns identity, permissions, limits, and cleanup at that boundary.
Anunix already has parent and child cell identifiers, lifecycle states, and execution policies.
The comparison baseline, `35d0245`, ignores the recursion permission and configured child limit during derivation.
It also omits the cognitive envelope when copying policies and retains destroyed children in the parent list.

## Scope

The source is [Day 006 in the daily review](daily-review.md#day-006--2026-07-01).
The source message identifier is `eb3a9f70-77e4-4830-a53d-3ad1d8b603a2`.
The implementation applies the briefing's scope hierarchy to Anunix cells.

## Implementation

Child derivation requires recursive execution permission and available depth under both configured depth limits.
It enforces the parent's configured child limit as well as the array capacity.
A zero child limit prohibits children.
The child inherits the parent's policies, including its cognitive envelope.

Admission checks the live ancestry chain before the handler runs.
Each child must appear in its parent's child list with the next recursion depth.
A child cannot expand execution permissions, numeric limits, or a required locality.
Zero cannot remove a bounded token, reasoning, latency, or cost limit.
Admission also detects an ancestor's permission revocation after derivation.

A parent with live children cannot be destroyed.
Destroying a child removes its identifier from the parent and returns the slot.
Completed, failed, and cancelled children retain their slots until their caller destroys them.
The [native regression](../../kernel/core/tools/research_day006.c) checks denials, inheritance, ancestor revocation, and cleanup after failing and successful handlers.

## Limits

These checks constrain declarations at admission; they do not meter cumulative subtree consumption.
The runtime still executes synchronously and the registry lacks concurrency protection for all operations.
The change does not add physical CPU or memory isolation, external-call preemption, or automatic reaping.
Raw kernel callers remain trusted and can access cell structures directly.
Anunix does not implement the briefing's Linux cgroups or BPF scheduler experiments through this change.
