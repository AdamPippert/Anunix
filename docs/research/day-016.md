# Day 016: Recheck authority at the dispatch boundary

The July 11 briefing makes tool mediation explicit and places resource changes at defined execution boundaries.
Anunix already has an effect protocol with prepared, dispatching, committed, restored, and unknown phases.
The comparison baseline, `658e0f5`, checks authority and data policy during preparation but permits dispatch after those conditions change.

## Scope

The source is [Day 016 in the daily review](daily-review.md#day-016--2026-07-11).
The source message identifier is `e5d6a0c6-bee9-48f7-bff4-00780959b7fb`.
This step strengthens the existing effect protocol at its final boundary before dispatch.

## Implementation

Preparation and dispatch both require a nonterminal owner with side-effect permission.
An active runtime caller must match that owner.
An unscoped kernel caller retains the existing trusted interface for acting on a named cell's behalf.

For a data-bearing sink operation, the object must still exist and its current sensitivity must fit the sink's current ceiling.
Deleted, tombstoned, or missing data objects cannot pass as public data.
A rejected dispatch leaves the effect prepared and invokes no transition to dispatching.

After dispatch begins, revocation does not undo the operation.
The protocol still permits settlement as committed, restored, or unknown under its existing rules.
Unknown remains terminal and cannot become a new dispatch.

The [native regression](../../kernel/core/tools/research_day016.c) revokes permission and changes data sensitivity between preparation and dispatch.
It checks missing data, cancelled and destroyed owners, and attempts by another active caller.
The active caller can still prepare and commit its own authorized effect.
A separate case records an unknown outcome after dispatch and rejects redispatch.

## Limits

This change governs callers of the effect protocol; it does not make every kernel transport use that protocol.
The external-cell runtime retains its separate admission and audit checks.
The protocol's records and policy structures remain accessible to trusted kernel code.
The current synchronous kernel model does not provide an atomic transaction with another process or external system.

This step does not implement inference gangs, token-boundary CPU reassignment, signed verdicts, or semantic classification.
Settlement still relies on the transport caller's evidence about what occurred.
