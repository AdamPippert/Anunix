# Day 026: Expire continuity preferences and recheck resident state

The July 21 briefing schedules session continuity with resident state, expected reuse, and the cost of retaining that state.
The comparison baseline, `654d3e8`, retains eligible session affinity without checking a state object or expiring that preference.
The baseline also has logical memory tiers and engine resource leases, but no connection between those records and session affinity.

## Scope

The source is [Day 026 in the daily review](daily-review.md#day-026--2026-07-21).
The source message identifier is `8f38db3a-f37c-44db-be06-1612a846def1`.
This step adds an optional continuity planner over the existing compatible-engine session API.
The planner changes placement advice; the planner does not reserve hardware or restore model cache data.

## Implementation

The [continuity hint](../../kernel/include/anx/route.h) names an engine and a versioned state object.
The hint also declares its creation time, expiry, expected return probability, and three cost estimates.
Schema version 1 accepts probability from zero through 1000 per mille.
Each cost accepts zero through 3,600,000 milliseconds.
The interval from creation to expiry must be positive and no longer than 30 seconds.

The [planner](../../kernel/core/route/continuity.c) compares the probability-weighted restoration cost with the sum of reservation and interference costs.
Equal benefit and cost do not retain the preference.
Malformed hints return `ANX_EINVAL` before changing session or result outputs.
An expired hint remains valid input but loses its reuse preference.

The planner first obtains candidates through the existing session planner and its current permission filters.
Only a feasible candidate can receive the continuity preference.
Network permissions, remote-model permissions, and locality constraints retain their existing checks.
The planner also checks the cell's optional identity commitment.

Usable state needs a nonempty sealed payload at the hinted object version.
The object must permit payload reads by the requesting cell.
The memory entry must be validated, outside quarantine, and resident in logical tier L0 or L1.
An unusable object removes the preference without blocking ordinary scored placement.

The planner selects the highest-scored feasible candidate after expiry or loss of reuse benefit.
The prior session engine does not retain an indefinite preference through this API.
Successful placement increments the existing placement count once.
A no-candidate error preserves both caller outputs.

The [native regression](../../kernel/core/tools/research_day026.c) prefers an eligible lower-scored engine with usable state.
The fixture falls back after expiry, high interference cost, zero expected reuse, stale validation, lost residency, denied reads, or a changed object version.
Network denial and a draining engine also remove the preference.
The test rejects malformed probability and an unauthorized remote-only pool without changing caller outputs.

## Limits

The hint associates an engine with state by caller declaration; the implementation does not inspect an engine's physical model or KV-cache contents.
The caller remains responsible for logical model compatibility across the supplied backend pool.
The memory tiers describe logical placement and do not measure physical GPU residency.

The cost estimates and expected reuse probability come from the caller.
The change adds no interference profiler, workload predictor, bandwidth reservation, or priority inheritance.
The ordinary session API retains its prior behavior unless the caller chooses the continuity API.

The synchronous fixture does not test concurrent memory-entry removal or engine replacement.
The existing memory entries have no lifetime reference count.
The fixture measures placement outcomes, not session completion time, cache recomputation, or scheduler overhead.
