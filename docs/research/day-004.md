# Day 004: Promotion against an installed incumbent

The June 29 briefing places workload profiling and comparison before policy promotion.
Anunix already provides Resource Twin snapshots and a capability promotion gate.
The baseline gate can overflow its signed arithmetic and accepts an unknown incumbent identifier.

## Implementation

The gate widens scores before subtraction and widens the candidate count before multiplication.
Every representable score difference and candidate-count threshold fits in the resulting 64-bit values.
Invalid trial arguments clear a supplied promotion decision.

A gated installation requires an existing incumbent with installed status and a registered engine.
An unknown incumbent returns `ANX_ENOENT`.
An inactive incumbent returns `ANX_EPERM`.
The gate leaves the candidate and incumbent unchanged after rejection.

The regression covers tied scores, extreme score differences, large candidate counts, and invalid trial lengths.
The regression then checks the actual capability installation path.
Tied trials preserve the incumbent's installed engine.
Unknown and suspended incumbents prevent installation.
A candidate that clears the margin can install against the original incumbent.

## Limits

The gate applies a deterministic minimum margin; it does not establish statistical significance.
Synthetic paired scores test the gate's decisions, not a measured scheduling improvement.
The caller still supplies the measurements and candidate count.
The change does not authenticate those measurements or bind them to a frozen workload profile.
Successful installation registers a candidate engine; it does not atomically replace an active routing policy.
The regression removes its test engines and retains retired capability records in the guest store.
