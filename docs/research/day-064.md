# Day 064: Bind inference evidence to the bytes consumed

The August 28 briefing argues that trust must survive the interval between validation and execution.
It connects delegation identity, effect deduplication, artifact versions, and verification at the point of computation.
At comparison baseline `4ae6479`, Anunix checks several source dependencies but lacks a prepared inference record linked to consumed-image evidence.
This step adds that record and verifies the private model copy immediately before CPU computation.

## Scope

The source is [Day 064 in the daily review](daily-review.md#day-064--2026-08-28).
The source message identifier is `76e08520-047b-4b16-ac49-9d6162e4dd1e`.
This implementation covers the bounded toy CPU adapter path, with sealed image and prompt objects.
It reuses signed identity commitments and existing Cell authority checks.

Earlier work already binds protected external operations to their source bytes and suppresses retries after ambiguous outcomes.
This step extends the point-of-use principle to native model computation.
It does not implement the briefing's proposed causal ledger across every execution domain.

## Implementation

The [model-use registry](../../kernel/core/anxml/model_use.c) supports 16 prepared records with unique identifiers and epochs.
A controller supplies the owner, a sealed adapter image, a sealed byte-data prompt, an output limit, and a random seed.
Images use schema `anx:model/toy-adapter/v1`, version `1`, and the existing bounded adapter format.
Prompts contain 1–1024 bytes, and the explicit output limit is 1–128 tokens.

Preparation reads both objects through the normal access-checked object API.
The record captures their identifiers, versions, sizes, sensitivities, and SHA-256 digests.
It also retains the owner, parent identity, current signed identity-record identifier, and a digest of the prepared request.
Caller edits to the original specification cannot change that record.

Execution requires the exact owner or controller, the current epoch, and a ready record.
It checks live Cell scope, execution contract, scheduler permission, identity commitment, and the owner's token ceiling.
It then rereads both sources and verifies their metadata, digests, and owner access.
A different identity commitment invalidates preparation even if its authority bits remain the same.

The [CPU generation path](../../kernel/core/anxml/anxml.c) snapshots its request and adapter before use.
For verified generation, it checks the copied adapter's digest immediately before populating the model's bigram table.
The check occurs inside the existing generation lock, before any response bytes are written.
A different effective token ceiling also prevents verified execution, preserving the prepared request's meaning.

After computation, the model-use path rechecks the owner and both sources before returning output.
Success records the consumed-image digest, output digest, output length, and generated token count.
The record becomes completed and advances its epoch.
Another execution attempt cannot consume that completed record again.

A rejected execution leaves the caller's response, receipt, and prepared record unchanged.
Inspection returns a copy of the receipt, and an executing record reports busy.
Only controller code can prepare or destroy records.
Removing a record releases its retained Cell reference.

## Native checks

The [regression](../../kernel/core/tools/research_day064.c) prepares an image that produces `AAAA` under a four-token limit.
It changes each source's version, payload, and read permissions after preparation and verifies rejection without output or receipt changes.
It also checks unsupported input sizes, the wrong image type, stale epochs, and a lowered owner token ceiling.

A test hook corrupts the private execution copy while leaving the sealed source object unchanged.
The point-of-use digest check rejects that copy before generation.
The next uncorrupted attempt produces `AAAA` and records the matching image and output digests.
Changes to the caller's copied token limit and seed do not change the prepared request.

The fixture then advances the owner's signed identity commitment with the same permissions.
An earlier unconsumed record becomes stale.
A fresh record binds the new commitment and another image that produces `BBBB`.
The actual owner executes that record inside its Cell, while a foreign Cell cannot inspect or execute it.
The completed receipt identifies the new image and identity record.

## Limits

Receipts are private, boot-local records; they are not signed, durable attestations or a persistent effect ledger.
The native image format and request digest use the current CPU representation.
This change does not define a portable model interchange format.

The check protects the prepared model-use path and its verified CPU generation helper.
Other existing model entry points retain their own admission rules and do not automatically issue these receipts.
All CPU generation paths now snapshot their request and adapter, but only verified generation requires an expected image digest.

The fault test deliberately modifies memory inside the research image.
Its controller-only injection hook is excluded from production builds.
This software check does not reproduce hardware streaming integrity, protect against a compromised kernel, or attest accelerator memory.
It does not establish nondeterminism quarantine, inference quality, or the performance measurements discussed in the briefing.
