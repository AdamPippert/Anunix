# Day 010: Cancellation and task reaping

The July 5 briefing connects agent resource management with admission, cancellation, and zombie reaping.
Anunix has lifecycle transitions and scheduler queues, but the comparison baseline, `21f7d71`, does not connect cancellation to queue ownership.
Cancelling a parent leaves child work queued, and the scheduler's cancellation function removes only one matching entry.

## Scope

The source is [Day 010 in the daily review](daily-review.md#day-010--2026-07-05).
The source message identifier is `ec9c71c0-8871-450a-944e-a28f73b3e2dd`.
This step cancels queued work and provides explicit cleanup for terminal child tasks.

## Implementation

Runtime cancellation removes every scheduler entry for the cell and walks its descendant scopes.
It preserves already terminal records while cancelling eligible descendants.
Known terminal cells cannot be enqueued again.
Terminal parents cannot derive or admit new child work.

A cell run requires the created state and holds a reference until execution returns.
A second run of an active or terminal cell returns `ANX_EBUSY` without changing its trace.
Destruction cannot free an active cell.
Cancellation during a synchronous handler is observed after the handler returns and produces `ANX_ECANCELED`.
The runtime preserves the cancelled state and writes a cancellation event.
Cancellation before execution also attempts to materialize a trace.

The new `anx_cell_reap_children` function removes terminal direct child tasks when they have no descendants or extra references.
Reaping returns their parent slots and removes remaining scheduler entries.
Callers must stop using pointers to reaped children.
Model servers, virtual machines, and other subsystem-owned cell types retain their separate teardown paths.

The [native regression](../../kernel/core/tools/research_day010.c) queues one child three times across two classes.
Parent cancellation removes all three entries without invoking the handler.
An extra reference prevents reaping; releasing it allows the child record to be removed.
Later calls test active lifetime, repeated-run rejection, self-cancellation, and slot reuse.

## Limits

Cancellation does not interrupt a synchronous handler or undo an effect it has already performed.
A descendant in a state that cannot be cancelled can cause a partial cancellation and an error result.
Reaping is explicit and applies to direct child tasks; callers reap deeper trees from their leaves.
The change does not introduce an autonomous reaper, rate-limit controller, or MLFQ scheduler.
The scheduler still accepts identifiers that do not resolve to a live cell, preserving its existing queue API.
Trace materialization remains best effort, and the runtime context remains synchronous.
