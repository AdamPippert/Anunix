# Day 001: External-call authority

The June 26 briefing separates probabilistic policy proposals from deterministic enforcement.
Anunix already defines Execution Cells and a side-effect policy.
The baseline runtime did not enforce that policy before an external handler ran.

## Scope

The source is the first entry in [the daily review](daily-review.md#day-001--2026-06-26).
The source message identifier is `38205a54-ff49-4d7e-90a3-354c4d155e1c`.
The comparison baseline is commit `543ada0`.

## Implementation

The runtime checks external-call admission before planning or handler invocation.
The default `execution.allow_side_effects` value remains false.
An unauthorized external cell returns `ANX_EPERM` and enters `ANX_CELL_FAILED`.
An external cell without a call descriptor returns `ANX_EINVAL`.
An authorized cell invokes its handler through the existing path.

The regression checks denial, authorized invocation, and a missing descriptor.
The same C regression runs in the host suite and the booted kernel.
The test preserves the guest's live stores.
The test unregisters its local handler and destroys its temporary cells.

The research command is available only in images built with `RESEARCH_TEST=1`.
The default is `RESEARCH_TEST=0`; changing the value rebuilds the kernel objects.
The runtime value cannot change after boot.

## Validation

Observed baseline: the host suite reports 58 passing suites and one failing suite.
The Jekyll guest also reports `RESEARCH day-001 FAIL rc=-101`.
The failure establishes that the baseline calls the handler without permission.

Observed candidate: the host suite reports 59 passing suites and no failures.
Both direct kernel boot and UEFI disk boot report `RESEARCH day-001 PASS rc=0`.
The final artifact identifiers and results accompany the validation record.

## Limits

The handler in this regression is local and deterministic.
The test exercises the real cell runtime, allocator, and trace path inside Anunix.
The test does not contact an external service.
The low-level transport API remains a trusted kernel API; its callers retain responsibility for authority checks.
Operation-specific capabilities and crash-durable effect reconciliation remain separate work.

## Reproduction

The [VM runner](../../tools/research_vm.py) accepts one kernel or one UEFI disk image.
The runner records the image digest, QEMU command, guest response, and serial output.
The runner exits unsuccessfully when boot or the native regression fails.

```sh
make test
make kernel ARCH=x86_64 RESEARCH_TEST=1
make ARCH=x86_64 RESEARCH_TEST=1 build/x86_64/anunix-qemu.elf
make -C boot/anxboot
sh tools/build-uefi-usb.sh
python3 tools/research_vm.py --image build/anunix-x86_64-uefi.img \
  --out-dir build/research-day001-result --test day-001 --revision COMMIT
```

The runner needs QEMU with KVM access and Python 3.11 or later.
The output directory must not exist before the run.
The default firmware path is `/usr/share/OVMF/OVMF_CODE.fd`.
The `--firmware` option changes that path for one run.
