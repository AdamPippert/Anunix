# Day 047: Reject infeasible policy compilation early

The August 11 briefing places cheap storage and resource checks before expensive policy evaluation.
Anunix already limits routing profiles to eight cases and retains private evidence before runtime selection.
The comparison baseline, `22bb730`, provides no caller-selected budget for artifact storage, compiler scratch, or simulation calls.

## Scope

The source is [Day 047 in the daily review](daily-review.md#day-047--2026-08-11).
The source message identifier is `25eede96-54b8-4ce0-9fe8-0ff73d6fab3d`.
This step applies the briefing's feasibility boundary to the native routing-profile compiler.
Anunix has no hardware-prefetch simulator or programmable hardware backend in this experiment.
The briefing's hardware results remain untested.

## Implementation

The [profile API](../../kernel/include/anx/route_profile.h) exposes a requirement calculation and a bounded compile operation.
The requirement calculation accepts one through eight cases and allocates no storage.
The requirement calculation derives costs from the compiler's actual native structures, rather than a candidate's claimed size.

| Budget | Calculated requirement |
| --- | --- |
| Artifact payload | The complete `anx_route_profile` structure, in bytes. |
| Compiler scratch | One profile, one Cell, and two Resource Twin structures, in bytes. |
| Simulation calls | Two calls per declared case: incumbent and candidate. |

The [compiler](../../kernel/core/route/profile.c) copies the caller's budget before checking those requirements.
The caller cannot enlarge the fixed case limit through a larger budget.
Insufficient storage returns `ANX_ENOMEM`; insufficient simulation capacity returns `ANX_EFULL`.
The compiler rejects these requests before allocation, issuance reservation, environment capture, or simulation.
Invalid counts and missing required arguments return `ANX_EINVAL` without changing output values.

The existing compile API supplies the calculated budget and uses the same bounded path.
Callers that need smaller limits use the bounded API directly.
Successful compilation retains the existing private receipt, environment checks, winner preservation, and runtime fallback behavior.
Compilation never changes global routing weights.
Active Cells cannot invoke either compiler entry point.

The [native regression](../../kernel/core/tools/research_day047.c) reduces each budget independently and checks that no artifact appears.
The regression also proves the feasibility check precedes validation of malformed policy weights.
A candidate at the calculated limits produces a sealed artifact and succeeds through ordinary runtime selection.
The regression checks unchanged global weights and rejects compilation from an actual active Cell.

## Limits

The byte budgets cover artifact payload and explicitly named compiler allocations.
They exclude allocator overhead, object metadata, provenance records, fixed issuance storage, and call-stack usage.
These budgets do not provide a physical RAM reservation or whole-kernel memory ceiling.
Simulation calls bound the number of Twin evaluations, not elapsed time or CPU instructions.

The caller's budget applies to one compilation; the compiler does not maintain a shared budget across concurrent callers.
The existing fixed issuance limit still constrains the number of active profile records.
This step does not generate hardware policies, alter CPU prefetchers, or measure throughput, cache pollution, or power.
The source's cross-layer optimization hypothesis needs a separate simulator and representative workload evaluation.
