# Day 022: Preserve signed authority across cell replacement

The July 17 briefing attaches authority to a stable agent identity across changes to processes, models, and skills.
The comparison baseline, `4d6e43c`, checks cell permissions and capability grants but has no implemented identity commitment.
The [persona proposal](../rfcs/RFC-0027-persona-objects.md) remains a draft.

## Scope

The source is [Day 022 in the daily review](daily-review.md#day-022--2026-07-17).
The source message identifier is `e3b5929c-297d-4584-a409-2ba221be3fa4`.
This step implements signed authority commitments that survive cell replacement within one kernel lifetime.
The implementation does not restore identities after reboot or implement the full persona proposal.

## Implementation

The [identity API](../../kernel/include/anx/identity.h) binds an agent identifier to one operator key and a sequence of commitments.
Each commitment contains its schema version, agent identifier, generation, authority mask, operator key, and predecessor digest.
The authority mask uses the four existing capability permissions: network access, remote models, cell derivation, and side effects.

The [registry](../../kernel/core/identity.c) supports 256 identities per kernel lifetime.
Trusted control code creates the signed first generation outside an active cell.
Later transitions need the pinned operator key's signature and the next generation after the current digest.
Invalid signatures return `ANX_EPERM`; stale transitions return `ANX_EBUSY`.
Malformed commitments return `ANX_EINVAL` before registry mutation.

The canonical representation has 108 bytes with a fixed domain marker and explicit integer encoding.
The existing Ed25519 implementation signs the SHA-256 digest of those bytes.
Each sealed state object contains the canonical commitment and its 64-byte signature.
An updated record names the preceding record as its parent.
The registry advances only after the new record seals successfully.
The deletion hold rejects ordinary deletion of the history.

Trusted control code can bind a registered cell before execution.
An active cell cannot bind another cell to an identity.
Derived children inherit the identity; ancestry checks reject a changed or removed child binding.
Replacement cells retain the same commitment without retaining the previous cell identifier.

The [runtime](../../kernel/core/exec/runtime.c) compares every bound cell's requested execution permissions with the latest commitment before admission.
Admission traces name the exact commitment record, including identity denials.
A signed revocation therefore constrains existing children and later replacement cells at their next admission.
Child derivation, effect preparation, effect dispatch, and capability installation also consult the current commitment.

The [native regression](../../kernel/core/tools/research_day022.c) rejects unsigned, incorrectly signed, altered, duplicate, and replayed commitments.
The regression reads sealed history and verifies each tested signature and predecessor link.
The fixture replaces a cell without changing its identity, then revokes side effects across a child and replacement cells.
A prepared effect remains prepared after revocation blocks dispatch.
A signed restoration creates a new generation and permits a later cell to execute.

## Limits

Identity binding is optional; a cell with a nil identity retains the prior permission behavior.
Trusted kernel code still owns cell structures and can bypass these APIs through raw mutation.
The deletion hold does not prevent forced deletion by trusted kernel code.
The registry has no disk replay, distributed revocation, key rotation, or recovery-key protocol.

The authority mask does not express budgets, model suppliers, host lists, memory schemas, spending limits, or arbitrary semantic effects.
The change adds no model migration, candidate deployment, or identity-wide resource accounting.
Revocation checks do not preempt an external handler or undo an effect that already dispatched.
The fixture measures functional outcomes; revocation latency and signature overhead remain unmeasured.
