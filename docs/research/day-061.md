# Day 061: Contain scheduling authority within a Cell hierarchy

The August 25 briefing argues for revocable scheduling grants beneath a conservative parent governor.
Its Linux example separates policy selection from CPU authority and contains a failing child scheduler within its subtree.
At comparison baseline `f39c6d4`, Anunix has flat priority queues and nested memory leases, but no corresponding CPU-dispatch authority hierarchy.
This step adds native scheduling domains with deterministic queue and execution checks.

## Scope

The source is [Day 061 in the daily review](daily-review.md#day-061--2026-08-25).
The source message identifier is `e2f849a1-d8d9-4741-9440-50fa333e1238`.
The native runtime executes Cells synchronously on the bootstrap CPU.
These grants constrain participating Cell families within that runtime; they do not implement Linux sub-schedulers or preemptive CPU isolation.

The briefing also discusses compact capability discovery and dependency-aware memory retention.
Anunix already has a scoped tool catalog and explicit semantic dependencies from earlier steps.
This day's implementation focuses on its new scheduling-authority gap.

## Implementation

The [domain registry](../../kernel/core/sched/domain.c) holds at most 32 private grants, with a maximum hierarchy depth of eight domains.
A grant binds a Cell identity to CPU eligibility, allowed queue classes, a maximum priority, and an optional absolute expiry.
Only CPU mask `1`, representing the bootstrap CPU, is supported.
Other nonzero masks return `ANX_ENOTSUP`.

Only the controller creates, revokes, or removes grants.
A root grant requires a root Cell.
A child grant requires a direct child of its parent domain's owner.
Child CPU rights, queue classes, priority, and expiry must fit within the parent's authority.
Each Cell can own one domain, and identifiers never repeat during the boot.

The registry retains the owner and its declared lineage.
Public views are copies; changing one cannot widen the private authority.
An owner can inspect its own grant, while a foreign Cell cannot.
Removal requires a terminal owner and no child domains, preventing a live revoked family from falling back to ordinary execution.

Revocation requires the current epoch and marks every descendant domain revoked.
It advances their epochs and retains those records until cleanup.
Cells without their own grant inherit constraints from domains along their ancestry.
Changed owner lineage, revoked ancestors, and expired grants deny dispatch.

The [scheduler](../../kernel/core/sched/scheduler.c) checks queue and priority authority before enqueueing.
Dequeueing removes entries that no longer pass those checks and continues to an eligible entry.
The [Cell runtime](../../kernel/core/exec/runtime.c) checks domain authority during admission and records a typed denial in its trace.
Direct execution therefore cannot bypass a revoked queue grant.

The runtime checks authority again at model-generation admission and after execution.
Both [external dispatch paths](../../kernel/core/exec/external.c) also recheck before invoking a provider.
Those checks define cooperative boundaries; a callback already executing between them is not forcibly interrupted.

## Native checks

The [regression](../../kernel/core/tools/research_day061.c) builds a root, child, grandchild, inherited leaf, and healthy sibling.
It rejects priority expansion, extra queue rights, unrelated parent grants, unsupported CPUs, duplicate grants, and malformed queue values.
Editing a copied grant or the owner's lineage cannot bypass admission.

The fixture queues three descendants before revoking their child domain.
All three lose dispatch authority, their queued entries are removed, and direct leaf execution fails before its tool callback.
The leaf's sealed trace identifies the scheduler-domain admission gate.
The healthy sibling still leaves its queue and completes its callback.

A separate grant expires after 250 milliseconds while its owner is inside a callback.
The callback then attempts ordinary tool dispatch, protected-operation dispatch, and model-generation admission.
All three return `ANX_ETIMEDOUT`, and neither provider dispatches.
The protected operation remains prepared for controller cleanup, and the runtime fails the expired run at its completion boundary.

## Limits

CPU eligibility is a permission, not an exclusive reservation, runtime share, or promised service floor.
Multiple domains can permit the same bootstrap CPU.
The existing scheduler still orders entries by priority; no generated child policy or independent scheduling algorithm runs here.
Cells outside a domain retain ordinary scheduling behavior.

The implementation does not provide SMP affinity, frequency control, time slicing, forced preemption, or rescue bandwidth.
Revocation prevents later admitted work, while expiry during execution takes effect at the next checked boundary.
It cannot undo effects completed before authority expired.

This step tests authority containment in the native Anunix VM.
It does not reproduce Linux scheduler behavior or the briefing's proposed latency, throughput, or efficiency targets.
