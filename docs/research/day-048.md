# Day 048: Preserve semantic dependencies and reject invalid reuse

The August 12 briefing treats readiness, provenance, and dependency lineage as distinct properties of a semantic working set.
Anunix already records semantic manifests and protects live workflow intermediates from memory eviction.
The comparison baseline, `be47141`, does not protect declared semantic dependencies or connect their memory validation state to reuse.

The source is [Day 048 in the daily review](daily-review.md#day-048--2026-08-12).

## Implementation

The [memory plane](../../kernel/core/mem/memplane.c) issues a fresh generation for each controller validation update.
New entries start with generation zero, which means no controller validation.
The sequence never reuses a generation after forgetting and readmission within the same boot.
Sequence exhaustion returns `ANX_EFULL` before changing the entry.
Invalid validation states return `ANX_EINVAL`; active Cells cannot grant validation through this API.

The [semantic manifest](../../kernel/core/workflow/semantic.c) records whether each declared resource belongs to the memory plane.
A memory-tracked resource must have state `ANX_MEMVAL_VALIDATED` and a nonzero generation at binding and reuse.
The manifest pins that generation alongside the existing object version, type, sensitivity, and content digest.
A change in memory tracking or validation generation returns `ANX_EBUSY`.
An invalid current validation state returns `ANX_EPERM`.

The semantic manifest format advances to `anx:workflow/semantic-manifest/v2`, with schema version `2`.
The larger reference records include memory validation identity.
Old manifests do not satisfy the new private format checks.
The continuation format remains unchanged; continuations already pin the complete semantic manifest.

The private guard retains every declared resource identifier and the manifest identifier.
The [workflow liveness check](../../kernel/core/workflow/workflow_object.c) protects that set while execution runs, pauses, or waits for human input.
Existing memory eviction, demotion, and forgetting operations use that liveness check.
Protection covers each declared provider in a dependency chain, even without an intermediate workflow output for that provider.

Invalidating an input blocks semantic resolution, resume, and checkpoint creation without consuming the paused continuation.
Protection remains active during recovery, so memory eviction cannot remove invalidated evidence needed for inspection.
Controller revalidation creates a fresh generation and therefore cannot silently revive the old binding.
After abort, the controller can create a fresh manifest and restart execution.

The [native regression](../../kernel/core/tools/research_day048.c) constructs a three-object dependency chain and an unrelated memory entry.
Eviction selects the unrelated entry while the workflow pauses.
The regression contests the root, checks unchanged continuation and trace state, rejects Cell self-validation, then revalidates and requires rebinding.
The regression also checks completed execution after rebinding and rejects an old generation after forgetting and readmission.

## Limits

The controller supplies the validation verdict; the kernel does not independently establish the truth of the evidence.
Resources outside the memory plane retain the existing object and permission checks without a memory validation requirement.
The private dependency set conservatively protects every declared resource for the live run.
The implementation does not calculate per-node last use or discover dependencies missing from the manifest.

Protection governs memory placement and forgetting, not explicit deletion of a State Object.
Deleting or changing a declared object still invalidates semantic reuse through the existing checks.
The memory registry retains its existing concurrency limits and placeholder reference release.
Direct trusted-kernel writes to public structures remain outside the API authority boundary.

This step adds no quality-aware paging, partial KV migration, reconstruction-cost optimizer, or asynchronous model evidence channel.
The briefing's performance targets and reported gains remain untested.
