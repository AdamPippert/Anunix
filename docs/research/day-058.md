# Day 058: Enforce cognitive ceilings before native inference

The August 22 briefing treats model choice, reasoning, and context as resources to budget before physical placement.
It also argues that unchanged controls should establish the noise floor for claimed improvements.
At comparison baseline `e3c41b7`, Anunix sends token limits to model servers, but specialized workflow inference bypasses the Cell's cognitive envelope.
This step enforces the existing per-generation token ceiling in that native inference path.

## Scope

The source is [Day 058 in the daily review](daily-review.md#day-058--2026-08-22).
The source message identifier is `98626b40-d8a8-4dc7-939d-9461ca4b487c`.
The briefing discusses the August 21 research feed.
The implemented ceiling bounds generated characters in Anxml's built-in toy model, where each character is one token.
It does not represent a measured quality target or a total allowance across multiple calls.

## Implementation

The [Cell runtime](../../kernel/core/exec/runtime.c) captures each envelope when execution starts.
The synchronous runtime keeps the previous captured context across nested execution.
The new limit helper applies the smallest nonzero ceiling among active contexts.
A changed declaration returns `ANX_EPERM`; a cancelled context returns `ANX_ECANCELED`.
Failed limit checks preserve their output.

The [Anxml generation loop](../../kernel/core/anxml/anxml.c) applies that limit before resetting its tables or producing output.
A zero request retains the existing default of 128 tokens, subject to the captured ceiling.
The output buffer still caps generation at 2047 tokens.
Direct generation, specialized workflow dispatch, and adapter generation reach the same check.
An unscoped controller retains the requested limit.

The [envelope setter](../../kernel/core/exec/cell.c) rejects mutations by active Cells.
Controller code can set an envelope while the target remains created.
The runtime also checks for declaration changes after execution and records a failed step before validation.
That check does not undo computation or effects already completed by the handler.

The workflow dispatcher now reads its prompt through an authorized object handle.
It accepts exactly one nonempty prompt object, containing at most 1024 bytes.
Malformed input returns `ANX_EINVAL` instead of silently truncating an oversized prompt.
A denied prompt read returns `ANX_EPERM` and leaves the output identifier nil.
The generated object records the prompt as its parent, the active creator, and inherited sensitivity.

The [adapter cache](../../kernel/core/anxml/adapter.c) hashes the effective token ceiling into its request identity.
A result generated under a four-token ceiling therefore cannot satisfy the same caller request in a context that admits sixteen tokens.
The existing adapter identity, generation, image digest, prompt, and seed checks remain part of that comparison.

## Native checks

The [regression](../../kernel/core/tools/research_day058.c) runs a three-node workflow inside an active Cell with a four-token ceiling.
The workflow reads a prompt, invokes specialized Anxml generation, and records the resulting object.
The baseline produces more than four tokens; the candidate produces exactly four tokens for the fixture's repeated-character prompt.
The fixture also checks output provenance, creator identity, and inherited sensitivity.

Direct calls exercise default requests, smaller requests, and requests above the output buffer limit.
A child with a two-token ceiling produces two tokens, then the parent again produces four tokens after the child returns.
A deliberate change to the parent's public envelope cannot raise the child's effective limit.
Restoring the declaration restores normal bounded generation.

Adapter generation produces four tokens and validates its cache key in that context.
An unscoped sixteen-token request rejects the key; an explicit four-token request accepts it.
Other checks cover denied prompt access, malformed input counts, active setter calls, and preserved response buffers after a denied generation.

Separate Cells exercise an unset ceiling, a one-token ceiling, declaration drift after execution, and cancellation before generation.
The unset ceiling retains the existing default and output-buffer behavior.
A final unscoped generation confirms that nested execution restores the previous context.

## Limits

The ceiling applies independently to each generation; repeated calls do not consume a shared workflow allowance.
The `max_reasoning_depth` field remains reserved and does not control a reasoning loop.
The runtime context remains synchronous and global; this change does not provide concurrent per-CPU execution contexts.
Other specialized dispatchers retain their existing behavior.

The fixture uses deterministic toy inference, not an external language model or accelerator.
The change does not select skills, compress context, estimate model quality, or implement a unified cognitive planner.
It does not add a statistical measured-null promotion gate or reproduce the briefing's cost and quality results.
The existing model-server path still receives its declared token limit through its separate runtime request.
