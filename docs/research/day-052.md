# Day 052: Release idle capacity and reacquire on demand

The August 16 briefing separates permitted capacity from resources committed at a particular moment.
Its examples combine CPU elasticity, predicted model residency, and preparation before application startup.
Anunix already has private phase ceilings and resizable leases, but the comparison baseline, `1e70525`, cannot park an active phase.

## Scope

The source is [Day 052 in the daily review](daily-review.md#day-052--2026-08-16).
The source message identifier is `aba76f45-4f15-42d7-a43b-d5f1d488eb4a`.
This step adds explicit parking and reactivation to the native phase broker.
It implements the capacity lifecycle through the existing reservation ledger.

## Implementation

The [phase API](../../kernel/include/anx/phase.h) now distinguishes parked phases from active reservations and completed phases.
Only controllers can park or reactivate a phase.
Parking preserves its owner, role, phase kind, and private contract.
The broker saves its current request privately, releases the lease, and clears the public reservation and lease identifier.
A new epoch invalidates requests issued before parking.

The [broker](../../kernel/core/route/phase.c) releases capacity only when recorded memory usage is zero and all child leases have been released.
It rejects a backing lease that disagrees with the phase view.
A parked phase cannot be resized, restarted as a new phase, or detached before completion.
Its owning Cell remains retained by the broker.

Reactivation checks the current epoch, owner status, and private contract before attempting a new lease grant.
The grant competes with all current reservations through the normal capacity checks.
Failure preserves the parked state, saved request, epoch, and caller output.
Success acquires a fresh lease identifier and epoch while preserving the task and phase identities.
The saved allocation reflects any resize before parking, rather than the original phase request.

Completion can discard a parked request without reacquiring resources, including after owner cancellation.
A terminal owner cannot reactivate a parked phase.
Caller changes to the original request or contract storage do not alter the broker's private entitlement.

## Native checks

The [regression](../../kernel/core/tools/research_day052.c) parks a 4,096-byte reservation using 25% accelerator capacity.
It verifies that all reserved capacity becomes available while the phase identity remains intact.
Recorded usage and even a zero-sized child lease prevent premature release.

Separate competitors exhaust memory and accelerator capacity after parking.
Both reactivation attempts fail and preserve the complete parked view.
After the competing reservations are released, reactivation restores the saved allocation under a fresh lease identifier.
A second cycle confirms that parking preserves a resized allocation of 1,024 bytes and 10% accelerator capacity.

The regression rejects stale epochs, repeated transitions, resize and detach while parked, and attempts to exceed the original contract.
An actual foreign Cell cannot invoke either capacity transition.
Cancellation prevents reactivation but permits completion and full cleanup.
Final ledger availability matches the values before the test.

## Limits

The entitlement is a ceiling and a saved request, without a guaranteed future reservation or capacity floor.
Parking does not suspend execution, reclaim CPU cores, unload models, or release physical pages by itself.
Controllers must quiesce users and accurately report usage before requesting the ledger transition.
The broker does not predict demand or trigger transitions automatically from workflow events.

The source's Linux control plane, asynchronous preparation, and three-policy performance experiment remain unimplemented.
No activation-latency, throughput, or prediction-benefit claim follows from this deterministic VM fixture.
