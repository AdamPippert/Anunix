# Day 043: Preserve semantic dependencies across workflow suspension

The August 7 briefing treats a paused workflow's semantic environment as a consistency boundary.
The comparison baseline, `e367e95`, provides guarded workflow reuse and issued continuation checkpoints.
Those mechanisms do not provide named semantic resources with explicit compatibility requirements for ordinary workflows.

## Scope

The source is [Day 043 in the daily review](daily-review.md#day-043--2026-08-07).
The source message identifier is `f6d60d8a-4387-4496-96d4-d12bd2211617`.
The briefing recommends manifests for prompts, models, tools, policies, skills, and retrieval resources, alongside compilation of repeated workloads.
This step implements manifest admission across suspension and checkpoint restoration.
The baseline fixture changes an out-of-band policy object while paused and exposes an unchecked resume.

## Implementation

The [semantic manifest](../../kernel/core/workflow/semantic.c) contains up to 16 named, distinct resources and 16 compatibility requirements.
Each resource declares an identifier, exact version, name, and semantic kind.
Each requirement names a consumer and provider and specifies the provider's expected identifier and version.
Conflicting requirements, duplicate resource names or identifiers, invalid kinds, and unavailable versions prevent binding.

The controller binds a manifest outside active cell execution and outside running or paused workflows.
Binding checks read access and rejects staged dependencies.
It records each dependency's type, sensitivity, schema fields, and payload digest, with a one MiB payload limit per resource.
The manifest also pins the workflow's native graph and execution policy.

The runtime seals the manifest as a structured state object and keeps its identifier and digest in an opaque workflow guard.
The manifest inherits the highest dependency sensitivity.
Normal object write rules protect the sealed payload, while the guard detects corruption of that payload during admission.
The resolver returns a named resource identifier only after checking the current manifest and all its dependencies.

Workflow start, resume, checkpoint save, and checkpoint restore reevaluate the manifest and current read access.
Changed graph, versions, schemas, payloads, or sensitivities return `ANX_EBUSY`.
Missing objects return `ANX_ENOENT`, and withdrawn read permission returns `ANX_EPERM`.
A failed semantic check leaves the existing continuation, trace, graph, and run state unchanged.

Resume checks occur before replacement or skip can modify execution state.
A bound manifest prohibits replacement of the failed node, even when its dependencies remain current.
Abort remains available after dependency drift or deletion.
The controller must abort the paused run before binding a changed semantic environment for a fresh run.

Continuation images now include the semantic manifest identifier and retain it among their pinned references.
Their native schema and URI advance to version 2 because the image layout changed.
Restore requires both the issued continuation and the current semantic manifest to match.
A rejected restore leaves the unloaded checkpoint unconsumed.

The [native regression](../../kernel/core/tools/research_day043.c) declares policy, embedding, and index resources.
It rejects mismatched provider identity, conflicting versions, unavailable versions, manifest corruption, and unknown resource names.
The fixture then pauses an actual workflow, withdraws policy access, and verifies that resume is denied.

After changing the policy through the object API, the fixture rejects retry, skip, and replacement.
It checks the original continuation digest, pointer, trace pointer, trace count, node kind, and suspended state.
A separate sequence saves and unloads a checkpoint, changes the policy, and verifies that restoration is denied without consuming the image.
A final unchanged sequence saves, restores, resumes, and completes successfully.

## Limits

The controller supplies the semantic kinds and compatibility declarations.
The kernel verifies declared identities and versions; it does not prove that an index was built with the claimed embedding model.
The byte-string fixture tests consistency enforcement without running embedding inference or measuring retrieval quality.

This manifest is an explicit admission contract for declared artifacts.
It does not discover hidden tool dependencies, rewrite model aliases, select physical engines, or capture every resource used inside an opaque cell.
Binding rejects subflow and agent-call nodes because this step does not implement semantic inheritance for delegated graphs.

Dependency checks remain separate object operations rather than one atomic multi-object snapshot.
The mechanism rejects missing historical versions instead of reconstructing them or silently substituting current versions.
It does not implement branch-merge validation, workload fusion, optimizer passes, or cross-reboot registry restoration.
Existing trusted-kernel access and registry concurrency limits still apply.

Version 1 continuation images cannot be read as version 2 images by this build.
The tests establish admission and preservation behavior without a latency, reconstruction-rate, or application-accuracy claim.
