# Day 041: Reject stale observations while retaining their history

The August 5 briefing proposes observation coherence and explicit supersession alongside ordinary resource scheduling.
The comparison baseline, `4f69932`, stores object metadata, provenance, and interface structure.
The baseline does not validate an observation against the current resource state before admitting its content.

## Scope

The source is [Day 041 in the daily review](daily-review.md#day-041--2026-08-05).
The source message identifier is `5eb9115d-a4bb-4478-b033-ef28b0a7dc95`.
The briefing recommends typed observations with current dependencies and explicit replacement relationships.
This step adds a bounded observation catalog and read gate beside the existing information catalog.
The baseline adapter carries observation metadata but reads its content without a coherence check.

## Implementation

The [observation catalog](../../kernel/core/icm/observation.c) accepts records from the trusted controller outside an active cell.
Each record names an owner cell, subject resource, content object, provenance object, representation kind, and coverage declaration.
The controller must name an existing, nonterminal owner.
The catalog defaults to empty and permits 128 simultaneous records.

Publishing records the identifier, version, type, sensitivity, and payload digest of each dependency.
Each dependency has a one MiB payload limit for hashing.
Content must be sealed, and provenance must be a sealed execution trace.
The content sensitivity must cover both its subject and provenance sensitivity.
Staged objects cannot establish a current observation.

Observation reads compare current dependencies with the recorded versions and digests before copying content.
The check also reevaluates read access to the subject, content, and provenance.
A changed dependency returns `ANX_EBUSY`; a deleted dependency returns `ANX_ENOENT`; access withdrawal returns `ANX_EPERM`.
An active cell can read only records assigned to its exact cell identifier.

The controller can supersede an earlier observation with a newer complete structured observation for the same owner and subject resource.
The replacement must describe the same or a later subject version and pass current dependency checks.
Partial, unrelated, older, and already superseded replacements cannot authorize supersession.
The catalog records the replacement identifier and rejects future observation reads of the earlier record.

Supersession preserves the historical content object and its ordinary access policy.
Releasing a catalog record also preserves its dependency objects.
Active cells cannot publish, supersede, or release records.
The catalog lock serializes release and supersession against the final content copy.

The [native regression](../../kernel/core/tools/research_day041.c) reads an observation, changes its subject through the object API, and rejects the stale read.
The failed read leaves the supplied buffer unchanged.
The fixture rejects incomplete and unrelated replacements, then supersedes a matching observation and checks its retained historical bytes.
It also rejects unsealed content, invalid provenance types, insufficient sensitivity, and withdrawn subject access.

The fixture invokes the observation gate through actual owner and foreign cell execution.
The owner receives the current content, while the foreign cell receives `ANX_EPERM`.
Deleting the provenance object makes the current observation unreadable through the gate.

## Interrupt regression found during validation

The first UEFI candidate failed the earlier Day 038 reuse check with `ANX_EBUSY` after rebinding an unchanged graph.
Repeated complete sequences reproduced the failure in both the original and diagnostic candidates.
The diagnostic output identified a graph digest mismatch before the second workflow dispatch.
The [initial failure](evidence/day-041/initial-uefi-failure.json) and [diagnostic sequence](evidence/day-041/diagnostic-full-stress-failure.json) preserve those results.

The x86 kernel build permitted the compiler to place local variables in the 128 bytes below the stack pointer.
Interrupt entry also writes below that pointer on the current kernel stack.
The [compiled SHA-256 compression routine](evidence/day-041/unfixed-hash-stack.asm) used this region for part of its message schedule.
Its lowest schedule address was 128 bytes below the allocated stack frame.

A native leaf-function regression fills 16 volatile words, invokes the timer interrupt vector, and verifies that every word survives.
The [unfixed build at `9194f4b`](evidence/day-041/interrupt-baseline-failure.json) fails this direct check with `-4110`.
The [Makefile](../../Makefile) now applies `-mno-red-zone` to x86 kernel C compilation.
The regression runs before the observation checks on x86 research kernels.
Other architectures and host tests do not execute the x86 interrupt instruction.

The [fixed UEFI stress sequence](evidence/day-041/fixed-full-stress-result.json) passes all 41 daily checks followed by 20 more Day 038 invocations.
The direct interrupt check also passes in both boot modes.

## Limits

The controller declares the observation's meaning and coverage.
The kernel checks identity, freshness, provenance availability, and scope; it does not prove that a payload accurately describes the subject.
The native fixture uses byte strings as observation content and does not capture a screen or contact an application service.

Callers must use the observation read API for current-context admission.
Ordinary object reads remain available for archival access and do not infer observation validity from catalog metadata.
The catalog retains records only for the current kernel lifetime and does not provide a durable message bus.

The dependency checks do not form one atomic snapshot across every object.
Concurrent subject or policy changes after validation retain the existing object-store concurrency limits.
The change adds no learned packet valuation, automatic screenshot suppression, context-token accounting, or reversible memory compression.
The tests establish admission behavior without a task-quality or context-cost claim.
