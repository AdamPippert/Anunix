# Day 024: Fence effects across an entire run

The July 19 briefing separates effect admission from the scheduler's pause and cancellation state.
The comparison baseline, `2b8df85`, checks individual cells and prepared effects but has no shared run fence.
Pausing one branch therefore cannot hold a sibling through the existing effect protocol.

## Scope

The source is [Day 024 in the daily review](daily-review.md#day-024--2026-07-19).
The source message identifier is `38396083-009d-4719-87bb-27720ab59c9d`.
This step adds a shared run fence for new governed effects and connects cell cancellation to that fence.
The fence does not undo an effect that already crossed dispatch admission.

## Implementation

The [fence API](../../kernel/include/anx/effect_fence.h) supports 256 run fences per kernel lifetime.
Each fence starts in `RUNNING` with epoch 1 and control generation 1.
Trusted control code binds a registered root cell before execution.
The binding cannot change through the API after assignment.
Derived children inherit the fence; ancestry checks reject a changed or removed child binding.

Any active branch can hold its own run through `anx_effect_fence_hold`.
The branch cannot release the hold or create a replacement fence.
Trusted control code changes fence state with the expected control generation.
A stale generation returns `ANX_EBUSY` without changing the fence.

| Current state | Accepted destination | Effect admission |
| --- | --- | --- |
| `RUNNING` | `HELD`, `CANCELLED`, `TIMED_OUT` | Open before the transition |
| `HELD` | `RUNNING`, `REJECTED`, `CANCELLED`, `TIMED_OUT` | `ANX_EBUSY` |
| `REJECTED` | None | `ANX_EPERM` |
| `CANCELLED` | None | `ANX_EPERM` |
| `TIMED_OUT` | None | `ANX_EPERM` |

The [implementation](../../kernel/core/cap/effect_fence.c) advances the epoch on permanent closure.
Control transitions and the final transition into effect dispatch use the same lock.
A prepared effect records its fence identifier and epoch.
Dispatch rejects a changed binding, stale epoch, held fence, or closed fence without changing the prepared phase.
Releasing a hold preserves the epoch, so an existing prepared effect can continue after approval.

The [runtime](../../kernel/core/exec/runtime.c) checks the run fence before admitting an external-call cell.
The admission trace records the fence identifier, epoch, and result.
The external-call registry also checks the fence before invoking a handler, including a nested invocation from an active handler.
Checked GUI focus and capability installation consult the same fence.

Cell cancellation closes the shared fence before cancelling and removing scheduled work from the cell subtree.
Sibling cells outside that subtree share the closed fence even before their scheduler states change.
Settlement of an already-dispatched effect still permits a confirmed result or an explicit unknown outcome.

The [native regression](../../kernel/core/tools/research_day024.c) requests a hold from one branch and checks a sibling's prepared effect and external-call admission.
The fixture confirms that harmless computation and an unrelated run can continue.
The regression releases the hold and dispatches the earlier prepared effect once.
Cancellation blocks a later prepared effect and a fresh cell bound to the cancelled run.
The fixture also checks sticky rejection and timeout states, plus settlement of an already-dispatched effect as unknown.

## Limits

Fence binding is optional; unbound cells retain legacy effect behavior.
The registry is volatile and has no crash recovery, durable verdict log, or logical-effect deduplication across separately prepared records.
Reusing the same dispatched record fails, but that check does not provide distributed exactly-once execution.

The hold rejects requests with `ANX_EBUSY`; the gate has no durable queue.
A cell whose admission fails becomes failed under the existing runtime behavior.
The controller must create another cell after release instead of rerunning that failed cell.
The timeout state needs an explicit controller transition and has no automatic timer.

The regression uses native handlers and prepared-effect records, not email, repository-push, or deployment adapters.
The change adds no network confinement or mediation of arbitrary kernel writes.
Already-admitted handlers can still finish effects through channels outside this protocol.
The synchronous fixture does not measure cross-processor races, admission latency, or durable throughput.
