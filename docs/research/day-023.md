# Day 023: Authorize focus against a current GUI observation

The July 18 briefing treats graphical controls as typed targets with supported actions and verifiable state changes.
The comparison baseline, `f0e4f56`, has accessibility nodes and focus events but no observation generation or caller check for assistive actions.
The baseline records click and scroll activation events without proving an application action.

## Scope

The source is [Day 023 in the daily review](daily-review.md#day-023--2026-07-18).
The source message identifier is `18e4cfa8-3933-472b-900e-800cd425e87a`.
This step implements a checked native focus action over the existing Interface Plane.
The test surface uses the headless renderer; the fixture checks kernel focus state rather than rendered pixels.

## Implementation

The [accessibility API](../../kernel/include/anx/a11y.h) returns a copied node with the current observation generation.
Nodes now declare visibility, enabled state, and one authorized cell identifier.
Zero-initialized nodes have no cell grant and cannot receive checked actions.
Trusted control code can update those fields at runtime.

The [implementation](../../kernel/core/iface/a11y.c) advances the generation after descriptor changes and successful assistive actions.
Removal and reinsertion of the same integer node identifier invalidate the prior observation.
An accessibility reset also advances the generation instead of reusing an earlier generation.
Counter exhaustion rejects new checked actions and descriptor updates with `ANX_EFULL`.

The checked API accepts only native focus actions.
The caller must have side-effect permission and satisfy its optional identity commitment.
The target must grant that caller access and identify a visible surface.
The control must also be visible, enabled, and focusable.

| Condition | Result |
| --- | --- |
| Malformed request or invalid action value | `ANX_EINVAL` |
| Click or scroll request | `ANX_ENOTSUP` |
| Stale observation generation | `ANX_EBUSY` |
| Missing grant or unsuitable control state | `ANX_EPERM` |
| Destroyed target surface | `ANX_ENOENT` |
| Successful focus change | Receipt with verified focus and the new generation |

The implementation sets input focus and reads the resulting surface identifier before returning a verified receipt.
A rejected request leaves the receipt unchanged.
The checked API consumes a successful observation, so replay needs a new observation.
An active cell cannot use the legacy action API or alter accessibility descriptors to bypass the grant.

The [native regression](../../kernel/core/tools/research_day023.c) tests stale identifier reuse and requests without a grant or side-effect permission.
The fixture rejects disabled, hidden, and unfocusable controls, unsupported actions, and destroyed surfaces.
The accepted request changes actual Interface Plane focus to the intended surface and returns the same surface in its receipt.
The fixture preserves prior focus and removes only its own surface and accessibility node.

## Limits

The checked action verifies focus state, not a click outcome, form submission, or external application effect.
The change adds no accessibility adapter for another operating system, OCR, visual fallback, coordinate action, or application benchmark.
The generation covers accessibility state; the API checks current surface visibility separately.
Unrelated accessibility changes can also invalidate an observation.

The synchronous fixture does not test concurrent surface destruction or focus changes on another processor.
Trusted kernel code retains direct input and surface APIs; this change does not isolate arbitrary kernel callers.
The receipt is transient and unsigned; the accessibility event ring can overwrite old entries.
The briefing's task-success and latency thresholds remain unmeasured.
