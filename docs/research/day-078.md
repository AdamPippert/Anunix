# Day 078: Reclaim state during checked model waits

The September 11 briefing treats idle intervals and lineage as resource-management inputs.
The source is message `04ea316e-9606-4726-8f4f-cf54680e81c2` in the [research conversation](https://chatgpt.com/c/6a3eabf4-cb88-83ea-942e-a601dd12b392).
AgentZip motivates work during model waits and representation choices across related sandboxes.
The briefing also connects early cache preparation and shared memory to a broader state scheduler.
This experiment applies the idle-window admission boundary to Anunix continuation caches.

## Comparison

| Area | Existing Anunix | Day 078 change |
| --- | --- | --- |
| Continuation waits | Tool waits retain caches; human waits can release reservations and hibernate | Model waits admit bounded reclamation while retaining their reservations |
| Lineage | Cells retain parent identifiers | Continuations capture the parent and reject later drift |
| Maintenance eligibility | Explicit hibernation checks current semantic state | Reclamation also binds the requested parent, model source, phase, and page budget |
| Restoration | Hibernation rebuilds its checked cache and reacquires capacity | Idle reclamation rebuilds its cache against the same existing reservation |

The [previous continuation experiment](day-068.md) supplies the checked cache and sealed journal.
The [implementation](../../kernel/core/workflow/continuation.c) extends those mechanisms rather than adding a second state registry.
The [header](../../kernel/include/anx/continuation.h) defines the new model-wait reason and idle request.

## Implementation

The controller declares a model wait through the existing pause interface.
That transition blocks continuation dispatch and cache use without releasing its capacity reservation.
The idle request binds the continuation epoch, phase epoch, actual parent, canonical model object, and maximum page count.
The implementation requires a non-root lineage and a positive page budget.
Each configured continuation has one reconstructible cache page.

The gate rejects runnable continuations, tool waits, stale epochs, wrong ancestry, changed model bindings, and insufficient budgets.
It also rechecks current owner authority, the sealed journal, committed semantic results, the model payload, and read access.
The phase check confirms the current lease and its reserved capacity.
Failure preserves the caller's output, continuation state, and cache.

Successful reclamation seals a transition event, releases the private cache pool, and enters the idle-reclaimed state.
The continuation retains its model reference, semantic checkpoint, phase, and lease identity.
A repeated reclaim attempt fails because the first attempt has consumed the eligible state.
The journal allocation remains separate from the reclaimed cache page.

Resume rebuilds and verifies the cache before making the continuation runnable.
It increments the cache generation and preserves the existing phase and lease.
Source drift or a restoration failure leaves the continuation waiting with no usable cache.
The runtime removes any newly allocated cache after a failed restore.
Only controller calls can change these lifecycle states; active Cells cannot reclaim their own or another continuation's state.

## Native checks

The [fixture](../../kernel/core/tools/research_day078.c) creates two sibling continuations with the same sealed toy model.
Each initially holds one physical cache page and a 4,096-byte reservation.
The controller reclaims each cache only after declaring its model wait.
The observed cache-page sequence is two, one, zero, then two after restoration.
The two reservations retain their combined 8,192-byte capacity throughout the wait.

The native checks reject these requests without changing the selected cache:

- A runnable sibling and a tool-wait interval.
- A zero-page budget.
- An unrelated parent or a changed actual parent.
- A different model object or stale continuation epoch.
- A stale requested phase or a changed actual phase.
- A changed canonical payload or revoked read access.
- Repeated reclamation after the cache is absent.

The fixture also changes the source version before resume and injects a failure after cache allocation.
Both failures preserve caller output and leave no cache page behind.
Successful retries retain each original lease and advance both cache generations.
Actual CPU generation returns `AAAA` from both restored caches.
Foreign inspection and active-Cell lifecycle changes fail.

## Limits

The controller supplies the model-wait declaration and maintenance request.
The kernel checks that declaration against its private continuation state; it does not predict future waits or observe a remote model service.
Lineage limits eligibility but does not compress, merge, or share sibling cache contents.
The experiment uses a 72-byte deterministic model in a dedicated physical page.

Reclamation removes reconstructible acceleration state while keeping the logical capacity reservation conservative.
Other continuations do not receive that reserved capacity through this API.
The fixture measures cache pages, not total memory after journal allocations.
It establishes no sandbox-concurrency, latency, energy, GPU, CXL, or storage-transfer benefit.
Lifecycle state and journals remain within the current kernel lifetime.
