# Day 076: Share immutable representations under an explicit memory contract

The September 9 briefing distinguishes semantic objects from allocations and physical materializations.
At comparison baseline `7c67532`, Anunix creates separate cache pools for resource-shape replicas.
This step can replace compatible immutable copies with aliases to one physical representation.
The controller checks applicability, current bytes, and a requested page saving before replacing the existing copies.

## Scope

The source is [Day 076 in the daily review](daily-review.md#day-076--2026-09-09).
The source message identifier is `b6df868e-dc4e-4388-b987-eb9f2591d320`.
The briefing discusses AutoUVM's semantic access visibility, DejaVu's shared representations, and validated procedural rewrites.
The native experiment applies the representation distinction to immutable CPU cache views.
It does not implement GPU prefetching, CUDA transformations, or a procedural graph optimizer.

## Comparison

Day 050 separates immutable logical views from private allocation details.
Day 060 moves views across pools while preserving aliases.
Day 074 versions the number of replica slots and invalidates outdated physical plans.
Those replicas still consume separate pages even when their verified bytes are identical.

The [extended contract](../../kernel/include/anx/resource_shape.h) declares the applicable topology and access requirements.
The [shape controller](../../kernel/core/route/resource_shape.c) checks those requirements and coalesces eligible replicas.
The existing physical-plan and model-use paths continue to enforce source identity and execute through immutable views.

## Implementation

The controller requests sharing for a specific shape epoch.
The request declares coherent CPU access, read-only consumers, and whether the copies provide write ordering.
It also supplies a minimum percentage reduction in physical pages.
The runtime accepts sharing only for coherent CPU access without write-ordering requirements.
Unsupported device topology or writable consumers leave the existing representation unchanged.

The shape cannot have an active execution.
The controller rechecks the current owner, identity, source, and live phase capacity.
The controller reads actual pool statistics to calculate the possible page reduction.
It checks every resident replica against the canonical sealed model bytes.
Each old pool must contain one physical page, one immutable record, and one private alias.
Failure before replacement preserves the old shape epoch and copies.

The controller allocates replacement aliases before removing old copies.
Allocation failure releases any new aliases and preserves the old representation.
After successful checks, the controller advances the shape epoch and replaces duplicate pools with aliases to one surviving pool.
The unused pools release their physical pages.
The shape records the shared, read-only geometry.

Earlier physical plans fail their captured shape epoch after coalescing.
The logical source identifier, source digest, program digest, and completed results remain unchanged.
Fresh physical plans read through the selected alias and invoke the existing verified CPU generation path.
The transformation provides no writable mapping to a consumer.

Later placement on an empty replica slot clones an existing shared view instead of allocating another data page.
Removing a slot releases that alias.
The controller destroys a shared pool only after the last alias disappears.
Statistics count each physical pool once while counting each resident replica slot separately.

## Native checks

The [regression](../../kernel/core/tools/research_day076.c) starts with two private pages containing the same 72-byte model image.
A requested saving of 51 percent rejects coalescing because the available reduction is 50 percent.
Separate-device topology, writable consumers, and copy-provided write ordering also reject the transformation.
Corrupting the canonical source rejects the transformation despite intact cached copies.
Every rejected case preserves the epoch, copy geometry, physical pages, and caller output.

The original representation then executes a logical operation and produces `AAAA`.
The controller issues another physical plan before requesting compatible sharing with a 50-percent threshold.
Coalescing reduces two physical pages to one and invalidates that issued plan.
The completed logical result remains available.

| Observation | Separate copies | Shared representation |
| --- | --- | --- |
| Initial resident replica slots | 2 | 2 |
| Physical data pages | 2 | 1 |
| Physical model payload bytes | 144 | 72 |
| Canonical model identifier | Original identifier | Unchanged |
| Logical program digest | Original digest | Unchanged |
| Verified operation output | `AAAA` | `AAAA` |

The fixture expands the shape to three slots and compiles a fresh placement on the new slot.
All three resident aliases still use one physical page.
The active owner completes the second logical operation through the new alias.
Foreign execution and active-Cell attempts to change the memory geometry are rejected.
Shrinking to one slot preserves the surviving page, and final cleanup releases the shared pool.

## Limits

The contract describes this CPU execution path; it does not discover or attest a physical GPU topology.
The controller remains responsible for declaring the access and ordering requirements correctly.
The immutable view API supplies the concrete read-only boundary used by the fixture.
No writable-buffer aliasing or synchronization-removal transformation is supported.

The admission metric is physical page count, not measured runtime profitability.
The experiment reports no memory-bandwidth, latency, energy, page-fault, or GPU utilization improvement.
The original phase reservation remains conservative and covers all configured replica slots after sharing.
Metadata, canonical objects, and execution buffers remain outside the reported cache page count.

Sharing is an explicit controller operation and advances the existing shape epoch.
The implementation has no automatic topology policy, optimizer model, or inverse expansion from aliases into copies.
All resource-shape state remains within the current boot.
The tests establish representation equivalence for the bounded immutable model image, not arbitrary application memory.
