# Day 049: Keep placement authority with the memory controller

The August 13 briefing separates semantic advice from ownership of placement, eviction, and effect commitment.
Anunix already bounds retention hints and reserves protection and pool eviction for the controller.
The comparison baseline, `cd5fc09`, still allows active Cells to invoke direct promotion, demotion, and forgetting APIs.
The baseline also treats validation states as a numeric trust scale during L4 promotion.

## Implementation

The [memory plane](../../kernel/core/mem/memplane.c) rejects promotion and demotion from active Cells with `ANX_EPERM`.
Only the controller can invoke those placement operations outside active Cell execution.
Existing tier protection and live workflow dependency checks still apply.

The controller also owns forgetting operations.
An active Cell can release its own charged admission through `ANX_FORGET_HARD_DELETE`.
That cleanup exception requires the stored admission owner to match the current Cell.
The exception grants no authority to archive, tombstone, rederive, or release another owner's entry.
Cleanup still respects protected tiers and live dependencies.

Releasing an owned admission remains possible after object-read permission is revoked.
The release removes the memory record and charge; it does not delete or expose the underlying State Object.
This behavior preserves the bounded admission and cleanup contract from Day 011.
An uncharged entry has no admission owner and therefore has no active-Cell cleanup exception.

L4 promotion accepts only `ANX_MEMVAL_PROVISIONAL` or `ANX_MEMVAL_VALIDATED`.
The check runs under the entry lock before the placement changes.
Contested, superseded, stale, quarantined, and unvalidated states all fail with `ANX_EPERM`.
The L5 path remains unavailable through this API.

Authorized retention hints still use the existing priority limit of 100 and lifetime limit of 16 sweeps.
Hints cannot modify a Cell's memory ceiling, create protection, promote an entry, or transfer ownership.
The [native regression](../../kernel/core/tools/research_day049.c) supplies maximum hints from an actual active Cell and exercises each authority boundary.

The regression fills an eight-byte admission budget and rejects another eight-byte object despite the hint.
The owner then releases its charge after read revocation and admits the next object within the restored budget.
The regression checks all five invalid L4 validation states and both permitted states.
Existing Day 011 and Day 020 regressions check compatibility with admission cleanup and controller eviction.

## Limits

Placement remains logical tier metadata; these APIs do not implement physical page reclaim or accelerator memory migration.
The controller remains responsible for selecting placements and validating capacity through the relevant resource mechanisms.
The existing admission API and its initial tier policy retain their behavior.
This step does not infer hardware coherence, create zero-copy model views, or import framework buffers.

Trusted kernel code can still access public internal structures directly.
The memory registry retains its existing concurrency and reference-lifetime limits.
The briefing's load-time, throughput, and memory-sharing gains remain untested.
