# Day 073: Preserve context permissions through derivation

The September 6 briefing proposes independently checked policy evidence and explicit protection for model context.
At comparison baseline `0d13e09`, Anunix validates candidate artifacts but has no compiler for context roles and scopes.
This step adds a typed compiler that preserves the lowest permission ceilings across each context segment's ancestry.
The compiler rejects unauthorized role or scope increases before returning any assembled bytes.

## Scope

The source is [Day 073 in the daily review](daily-review.md#day-073--2026-09-06).
The source message identifier is `3693656d-55cf-4075-85be-4d4e1312fb62`.
The briefing discusses MachCSL, context privilege escalation, and identity continuity across execution runtimes.
Its proposed Context MMU labels source content with provenance and permission ceilings.
The native experiment implements that bounded context boundary.
It adds no formal kernel proof or persistent identity migration.

## Comparison

Days 044 and 046 bind policy validation to source, environment, artifact identity, and passing evidence.
Those gates provide checked evidence rather than machine-checked correctness theorems.
Day 072 checks evidence ancestry before an enrolled staged mutation commits.
None of these gates represents the role or storage scope assigned to assembled model context.

The [public types](../../kernel/include/anx/context.h) distinguish imported sources, derived sources, and compiled segments.
The [implementation](../../kernel/core/state/context.c) stores immutable permission ceilings beside captured source identity.
The owner can derive context and compile permitted segments.
Only the controller can assign an imported root's origin.

## Implementation

The compiler uses four ordered role levels and four ordered scope levels.
These levels are local compiler labels, not hardware privilege rings or storage namespaces.
The fixed origin table supplies the initial ceilings.
The table has no runtime configuration or promotion API.

| Imported origin | Role ceiling | Scope ceiling |
| --- | --- | --- |
| Tool output | Tool | Session |
| User input | User | Session |
| Repository content | User | Project |
| Controller policy | System | Machine |

The controller imports a sealed byte object with no parents.
The record captures its owner, owner ancestry, identity record, object identifier, version, sensitivity, payload length, and payload digest.
The registry holds at most 32 records.
Each source contains between one and 4096 payload bytes.

A derived record names one to four existing context parents owned by the same Cell.
Its source object's actual parent identifiers must match those parent records in order.
The derived role and scope ceilings equal the respective minimum ceilings among all parents.
The derived sensitivity cannot be lower than any parent's captured sensitivity.
The registry rejects repeated parent records and derivation beyond seven edges from a root.
References prevent removal of parents while derived records depend on them.

The compiler accepts one to eight requested segments and at most 4096 assembled bytes.
Each request names a private record and a desired role and scope.
The compiler rejects a desired label above the record's ceiling.
It retains explicit offsets, lengths, roles, scopes, identifiers, and digests in the output bundle.
It does not flatten every segment into a single instruction role.

Compilation rechecks the owner's identity and scope and each source's sealed state, bytes, version, parents, sensitivity, and read access.
The runtime checks access as the logical owner.
Active compilation also records reads in the existing effect fence.
A final ancestry check precedes publication of the complete bundle.
Any failure preserves the caller's entire output buffer.

The owner or controller can inspect current records and compile permitted context.
Foreign Cells cannot read or derive those records.
Only the controller can remove records, and referenced parents return `ANX_EBUSY`.
Copied observations and bundles grant no authority over the private records.

## Native checks

The [regression](../../kernel/core/tools/research_day073.c) imports tool, policy, repository, and user sources.
It derives a summary from policy and tool content, then derives another summary from that result.
Both summaries retain tool-role and session-scope ceilings.
The fixture tests every combination of the four requested roles and four requested scopes against that low-trust ancestry.
Only tool-role, session-scope assembly succeeds.

The fixture places an allowed policy segment before the rejected segment.
Rejection still leaves the whole output unchanged, rather than exposing a partial bundle.
Changing copied ceiling fields cannot affect the private ancestry.
A derived source cannot enter again as a parentless policy root.
Wrong declared parents and foreign ownership also reject derivation.

Injected changes to an ancestor's actual payload, version, parent identifier, or read policy reject assembly.
An empty specification and an oversized combined payload also reject assembly without changing output.
Each fault is restored before the next check.

An active foreign Cell cannot inspect, derive, or compile the owner's context.
An active owner cannot import tool bytes as policy or remove a record.
The owner can create another derived copy and compile a two-segment bundle.
That bundle preserves system-role policy and tool-role copied content as separate segments with exact expected bytes.
Controller cleanup releases all context records and their Cell references.

## Limits

This compiler is an opt-in API, not a mandatory boundary around every existing model or memory operation.
Consumers must preserve the emitted labels and use fresh compilation for current ancestry checks.
Copying a returned bundle does not preserve a live authorization grant.
Scope labels do not themselves persist data, enforce storage namespaces, or isolate accounts.

The controller remains trusted to assign imported origins correctly.
The policy origin does not imply a verified digital signature.
Declared ancestry cannot reveal omitted real-world dependencies or prove that a summary accurately describes its parents.
The implementation includes no semantic sanitizer, model evaluation, or automatic trust promotion.

All context records remain within the current boot.
The fixture measures deterministic label enforcement, not resistance across a production agent harness.
The Context MMU name describes the research analogy; this implementation adds no hardware memory protection.
Existing policy evidence gates remain tests and deterministic checks, not a Rocq proof of Anunix.
