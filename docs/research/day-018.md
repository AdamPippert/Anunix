# Day 018: Bind build profiles to tested images

The July 13 briefing separates build configuration, runtime policy, and scheduler dispatch into different optimization loops.
Anunix builds a native kernel through Make; Linux Kconfig is not its configuration mechanism.
The comparison baseline, `01c91d6`, records artifact hashes but has no compiled configuration profile or guest compatibility check.

## Scope

The source is [Day 018 in the daily review](daily-review.md#day-018--2026-07-13).
The source message identifier is `0f7ae5cd-ece1-4b5f-917c-cdcd0ae3339e`.
This step adds an unsigned profile for the compiled architecture and research instrumentation mode.
The profile describes a build; the profile does not authorize deployment or modify runtime policy.

## Implementation

The kernel exposes an immutable descriptor through [kernel_profile.c](../../kernel/core/tools/kernel_profile.c).
The descriptor records schema version 1, the compiler target architecture, and research instrumentation mode.
The existing Make setting `RESEARCH_TEST` defaults to `0`; `1` includes the native research fixtures.
Both descriptor fields remain fixed during execution.

The native compatibility check returns `ANX_EINVAL` for malformed descriptors and `ANX_ENOTSUP` for incompatible architecture or instrumentation requirements.
The check accepts the running configuration and never modifies the descriptor.
The [native regression](../../kernel/core/tools/research_day018.c) checks valid, incompatible, malformed, and null requirements.

The [profile tool](../../tools/kernel_profile.py) records the artifact's SHA-256 digest, size in bytes, compiled configuration marker, and caller-declared revision.
Every configuration marker within an artifact must agree, including the kernel and its legacy wrapper within a disk image.
The validator rejects unexpected fields, duplicate JSON keys, malformed values, changed artifacts, and inconsistent configurations.

The [VM runner](../../tools/research_vm.py) accepts an existing profile through `--profile` or captures one before boot.
The runner requires `x86_64` and research mode `1` before it starts QEMU.
The guest's `sysinfo` output must match the profile before native tests execute.
The runner rechecks artifact identity after those tests, then stores the profile and result together.

The [host profile tests](../../tests/test_kernel_profile.py) cover altered images, incompatible modes, contradictory markers, malformed profiles, and guest mismatches.
The preflight regression checks that an incompatible profile stops the runner before QEMU starts or a result directory appears.
The existing `make test` target runs these checks after the native host suites.

## Limits

The profile provides compatibility checks and artifact identity; the profile does not prove authenticity or source provenance.
The declared revision comes from the caller and does not attest the build inputs.
The descriptor covers architecture and research instrumentation, without compiler flags, toolchain versions, or individual driver selections.
The lab assumes trusted, stable artifact files; the profile does not provide secure boot or protection against a malicious build worker.

This change adds no configuration generator, Linux Kconfig support, performance optimization, signing service, or automatic promotion.
The briefing's reported performance gains remain untested.
