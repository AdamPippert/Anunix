# Day 069: Execute from the next materialized frontier

The September 2 briefing separates logically live state from the state needed for the next useful operation.
At comparison baseline `6eb8078`, Anunix reconstructs one continuation cache before resuming its dispatch.
This step adds an ordered frontier across several prepared model operations.
The experiment compares complete restoration with incremental restoration through the same verified CPU execution path.

## Scope

The source is [Day 069 in the daily review](daily-review.md#day-069--2026-09-02).
The source message identifier is `1afdd52b-e9ef-42cc-b612-97e2606d48d0`.
The briefing derives its frontier proposal from mzCache's restoration ordering and AInfer-PD's explicit phase ownership.
Its broader proposal makes restoration schedulable work with dependency boundaries.
The native experiment tests that contract with independent toy-model images.
It does not reproduce either paper's latency measurements or concurrent GPU restoration.

## Comparison

Day 060 moves immutable physical views while retaining logical identity.
Day 064 checks the exact source and image consumed by model execution.
Day 065 executes a fixed graph of prepared model operations.
Day 068 separates a continuation's semantic checkpoint from one reconstructible model cache.
Those mechanisms do not expose partial readiness across an ordered sequence of model images.

The [frontier implementation](../../kernel/core/mem/frontier.c) stores up to eight prepared operations per private record.
The registry permits 16 records and copies each specification before validation.
Each operation names a distinct prepared model-use identifier and dependencies on earlier operations.
The owner, operation bindings, execution order, and phase epoch remain fixed.

## Implementation

Creation requires an active inference phase and ready model operations belonging to the same owner.
The controller chooses one of two modes at creation.
The mode cannot change through the public view.

| Mode | Requirement before the next operation |
| --- | --- |
| Full restoration | Every unfinished operation has a resident model image |
| Incremental restoration | The next operation has a resident image and completed predecessors |

The restore API materializes the earliest missing image after the execution cursor.
It checks the original source's version, digest, schema, sensitivity, and current access rules.
Each image occupies one dedicated resource page, with private pool and view handles.
The reclaim API selects the farthest resident image beyond the cursor.
It frees that page while retaining the immediate frontier.

Each mutation checks the captured phase epoch and current lease dimensions.
Revoked, expired, missing, parked, or changed reservations block progress.
Frontier records belonging to one owner share the phase's page allowance.
Another record cannot allocate beyond that allowance by presenting the same phase reservation.
Owner scope, execution constraints, identity admission, and scheduler-domain checks also remain active.

The step API advances one operation and verifies its declared predecessors.
It reads the actual private resource view through the [model-use execution path](../../kernel/core/anxml/model_use.c).
That path checks the source objects before execution and validates the cached image inside the verified CPU path.
It checks the sources and owner again before publishing the model-use receipt.
The frontier checks its phase again before advancing the cursor and returning output.

Only the owner or controller can step, inspect, or read a completed operation.
Only the controller can create, restore, reclaim, or destroy a frontier.
An active step blocks mutations of its private buffers.
Restoration and execution alternate at explicit boundaries; they do not execute concurrently in this implementation.

A rejected preflight preserves the cursor, epoch, completed bits, and caller output.
A corrupted cached image leaves the underlying model operation ready for a corrected attempt.
A phase change after successful model execution can leave a model-use receipt without advancing the frontier.
The resulting epoch mismatch blocks replay through that frontier.
Controller cleanup releases its private pools and owner reference.

## Native checks

The [regression](../../kernel/core/tools/research_day069.c) creates sealed model images that generate `AAAA` and `BBBB`.
It restores both images, reclaims the later image, and observes returned physical pages.
The immediate frontier remains resident and cannot be reclaimed through the future-state policy.
A phase resize then makes the earlier frontier stale.
Both restoration and execution reject that stale phase.

The full-restoration case rejects execution after only its first image becomes resident.
After both images become resident, it generates the expected outputs in order.
A competing frontier cannot exceed their shared 8192-byte page allowance.
Destroying the completed full-restoration record returns capacity for the incremental case.

The incremental case corrupts its first cached image and checks unchanged output and progress after rejection.
After correction, it executes the first image while the second image remains absent and its source bytes differ.
Restoration rejects those changed future bytes when they become necessary.
Restoring the original source permits the second operation to proceed.

| Fixture measurement | Full restoration | Incremental restoration |
| --- | --- | --- |
| Managed image bytes restored before first useful work | 144 bytes | 72 bytes |
| Managed pages before first useful work | 2 pages | 1 page |
| Final generated outputs | `AAAA`, `BBBB` | `AAAA`, `BBBB` |

The fixture also rejects a malformed dependency.
Mutations of a copied specification have no effect.
A foreign active Cell cannot inspect, step, or read the frontier.
The active owner executes the final model operation and reads the earlier completed result.

## Limits

The frontier covers independent 72-byte model images, not transformer layers, KV blocks, compiler processes, or general agent sandboxes.
The canonical source objects, prompts, receipts, pool metadata, and temporary CPU copies remain outside the managed image-byte count.
Source validation still reads canonical bytes before and after model execution.
The fixture therefore measures the managed restoration contract rather than storage traffic or total process memory.

The phase allowance covers pages allocated by frontier records for that owner.
It does not charge unrelated resource pools or metadata against the same allowance.
The controller retains responsibility for those separate allocations.
The immutable plan assumes a declared forward execution order; it does not predict branches or future use.

The experiment establishes correctness with fewer managed bytes restored before the first result.
It does not establish a latency improvement, a throughput improvement, or the briefing's proposed 25% threshold.
The existing continuation suspension API remains separate from this ordered model-work primitive.
The source objects and private records remain within the current boot.
