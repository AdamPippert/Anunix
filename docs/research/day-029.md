# Day 029: Retain workflow intermediates until their consumers finish

The July 24 briefing connects causal diagnosis with the value of retaining expensive workflow intermediates.
The comparison baseline, `ff868c8`, tracks workflow ports and unfinished nodes, but memory eviction does not consult those dependencies.
A high decay score can evict an intermediate despite an unfinished workflow consumer.

## Scope

The source is [Day 029 in the daily review](daily-review.md#day-029--2026-07-24).
The source message identifier is `1786af0d-1948-4d58-aada-fa836093fddc`.
This step connects produced workflow inputs to logical memory retention.
The implementation adds no Kubernetes remediation controller or measured recomputation-cost policy.

## Implementation

The [workflow executor](../../kernel/core/workflow/workflow_exec.c) records output object identifiers whose outgoing edges lead to unfinished consumers.
The executor refreshes that set before dispatch and after each successful node.
The set contains at most 128 unique identifiers, bounded by the workflow edge limit.
Duplicate references retain one entry.

The [workflow registry](../../kernel/core/workflow/workflow_object.c) checks all running, suspended, and human-review workflows for a live reference.
Completion, failure, abort, or destruction removes that workflow from the liveness decision.
A shared intermediate remains live while another active workflow still references it.
Invalid edge bounds or endpoints make the recorded liveness unknown and conservatively prevent reclamation while that workflow remains active.

The [eviction selector](../../kernel/core/mem/retention.c) excludes those live intermediates before applying existing decay and retention scores.
An eligible intermediate with no unfinished consumer remains reclaimable, even with a lower eviction score.
An all-live candidate pool returns `ANX_ENOENT` without changing the victim output.
The direct demotion and forgetting APIs return `ANX_EBUSY` for changes that remove live placements.

Node and edge mutation APIs reject topology edits while a workflow is active or paused.
The existing resume operations retain their separate retry, skip, replace, and abort behavior.
A resume refreshes liveness from its saved execution state before dispatch.
Completed workflows permit topology edits again.

The [native regression](../../kernel/core/tools/research_day029.c) pauses two workflows at a denied capability-promotion consumer.
The fixture evicts their unused intermediate and retains the shared input despite its higher decay score.
Skipping one consumer preserves the other workflow's reference; aborting the other permits eviction.
The test also checks direct demotion, every forgetting mode, and blocked topology edits.
A workflow waiting for human review retains its input until destruction.

## Limits

Retention covers already-produced objects on direct edges to unfinished consumers.
The implementation does not predict transitive recomputation cost, invocation frequency, reuse probability, or critical-path savings.
The fixture measures retention decisions, not the briefing's reported latency improvements.

The memory tiers remain logical records; this change does not move or free physical GPU cache data.
This step adds no cache-reuse path or freshness validator.
Retention does not upgrade an object's validation state or grant payload access.
Direct object deletion and raw registry mutation remain trusted kernel paths outside this retention rule.

The registry preserves the existing limits of 16 workflows and 128 edges per workflow.
A paused workflow can retain its inputs indefinitely; this change adds no expiry, pressure override, or durable restart recovery.
The current executor dispatches synchronously, and the fixture does not establish atomicity under concurrent workflow mutation or memory-entry removal.
