# Day 063: Validate a control image before it can execute

The August 27 briefing treats an agent harness as an explicit control program with a stable interface.
Its generated instructions can select authorized operations, while the host retains authority over capabilities and execution limits.
At comparison baseline `0bf1fce`, Anunix has workflows and verified model-branch groups but lacks a typed control-image loader.
This step adds a bounded program format, validation, and an executor with separate control state and event history.

## Implementation

The [control-image interface](../../kernel/include/anx/control_image.h) defines a 336-byte program with an ABI version and at most 16 instructions.
Every word uses little-endian encoding; unused instruction slots and the reserved field must be zero.
The image must be a sealed structured-data object with schema `anx:harness/control/v1` and schema version `1`.

A separate controller grant supplies an operation mask, a step limit, and up to four model-group identities.
Each group must belong to the owner and be ready at creation.
The private registry copies the grant and decoded program, retains the owner, and captures group epochs and the image digest.
Changing caller-owned copies cannot change the issued program or its authority.

| Instruction | Meaning | Required state |
| --- | --- | --- |
| Run | Execute an authorized model group. | The group has not been run on this path. |
| Verify | Check the group's completed result. | The path has run the group. |
| Read | Copy an accepted branch result. | Every incoming path has verified the group. |
| Return | Complete the control program. | Every incoming path has produced a readable result. |
| Fail | Stop with a recorded failure. | No result is exposed. |

The [validator](../../kernel/core/workflow/control_image.c) requires forward transitions, reachable instructions, valid branch indices, and a bounded longest path.
It rejects unknown operations, undeclared slots, repeated runs, unverified reads, and returns without results.
Its dataflow checks intersect required state at joins, so one valid predecessor cannot conceal an invalid path.

Each step requires the current control epoch and rechecks owner scope, execution contract, identity, and scheduler authority.
It rereads the sealed image through the object API and checks its version, schema, sensitivity, digest, and owner access.
Group operations also require the captured group epoch.
A rejected step leaves the program counter, event count, epoch, and caller output unchanged.

An admitted instruction runs while the control is busy, preventing concurrent stepping or destruction.
Control-view reads return busy during that interval.
Completion appends one event and advances the program counter and epoch.
Earlier events remain unchanged; they are copied through a separate read API.

Model failure can select a recovery edge without erasing the failed attempt.
Result return and later reads recheck the underlying group and prompt access before exposing cached bytes.
Only the owner or controller may step, inspect, or read the control.
Creation and removal remain controller operations.

## Native checks

The [regression](../../kernel/core/tools/research_day063.c) rejects 11 malformed images and invalid authority grants before model execution.
These include cycles, unsupported versions and operations, undeclared slots, premature reads and returns, repeated runs, and insufficient step limits.
It also rejects an unsealed image and a group owned by another Cell.

The valid image first runs a model group that fails its expected-output check.
It then runs a second group, verifies `BBBB`, reads that result, and returns successfully.
The five events preserve the first failure and record the recovery path `0, 4, 5, 6, 7`.
The actual owner executes the recovery steps from within its own Cell run.

More checks cover stale control and group epochs, source corruption, revoked image access, copied-input changes, and immutable event history.
A foreign Cell cannot inspect or operate the control.
Short buffers and completed-control stepping fail without exposing extra data.
Revoking prompt access prevents a later result read.
An explicit failure program records one terminal event and exposes no result.

## Limits

The registry supports 16 boot-local controls and does not persist programs' execution state across restart.
Its fixed forward-only language excludes loops, arbitrary calls, generated native code, and external side effects.
The existing model groups provide exact expected-output verification for bounded toy-model candidates.
This validation does not establish reasoning quality or prove arbitrary generated software correct.

The executor runs synchronously and does not provide parallel acceleration, prefix-cache scheduling, or Linux scheduler integration.
Its events describe this control interface and do not replace durable workflow traces or records of external transactions.
No performance or model-quality result from the briefing is reproduced here.
