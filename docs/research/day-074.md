# Day 074: Version resource shape without changing the logical program

The September 7 briefing separates resource configuration from individual task placement.
At comparison baseline `4fe4bb0`, Anunix preserves logical progress across phase changes but has no separate resource-shape epoch.
This step adds a mutable cache replica configuration and binds physical plans to its epoch.
Changing that configuration invalidates earlier placements while preserving logical sources and completed work.

## Scope

The source is [Day 074 in the daily review](daily-review.md#day-074--2026-09-07).
The source message identifier is `a3296827-dc83-4a98-ab4d-a033c2db25f9`.
The briefing uses Vertumnus to distinguish fast request placement from slower changes to worker geometry.
It also discusses stable logical cache identity, lazy materialization, and resource escalation after task failures.
The native experiment tests versioned cache geometry and stale placement rejection.
It does not reproduce GPU context parallelism or the briefing's workload performance results.

## Comparison

Day 050 provides immutable resource views backed by private physical pages.
Day 069 distinguishes model readiness from execution readiness across a frontier.
Day 071 issues physical prefixes separately from the logical program and checks the current resource phase.
A phase epoch alone cannot identify a change in the number of cached physical representations within the same phase.

The [resource-shape API](../../kernel/include/anx/resource_shape.h) adds that separate identity and epoch.
The [shape controller](../../kernel/core/route/resource_shape.c) manages private replica pools.
The [physical planner](../../kernel/core/workflow/execution_shape.c) captures the shape epoch and selected replica.
Shaped execution consumes the selected private representation through the existing verified model-use path.

## Implementation

The controller creates one shape per owner, with one to four replica slots for a sealed toy-model source.
The registry holds at most eight shapes.
Each record retains the owner's Cell, ancestry, identity record, and exact source version, size, sensitivity, and digest.
Creation reserves no physical cache pages.
The active inference phase must cover one 4096-byte page for each configured replica slot.

A shaped physical plan captures the logical graph epoch, phase epoch, shape identifier, shape epoch, and replica index.
Compilation checks the graph's model source against the shape's captured source.
The first placement on an empty slot creates a private pool and copies the verified model image into one physical page.
Other slots remain empty until placement selects them.
Issued plans retain the shape until controller cleanup.

| Shape transition | Logical state | Physical state |
| --- | --- | --- |
| Create one replica slot | Source identifier and bytes unchanged | No materialized page |
| Compile a placement | Logical program unchanged | Selected replica materializes |
| Increase replica slots | Completed work and source unchanged | New slots remain empty |
| Place work on a new slot | Logical program unchanged | New replica materializes |
| Remove replica slots | Completed work and source unchanged | Removed private pages are released |

Changing the replica count advances the shape epoch before removing any old replica.
An unchanged count leaves the epoch intact.
The controller can resize a shape with issued plans; those plans then fail their captured epoch check.
Active execution blocks resize and destruction.
The implementation serializes execution within each shape.

Commit checks the shape's owner, source, current epoch, selected slot, and live phase capacity.
The existing physical planner also checks its captured phase and logical epochs.
Generation reads the private replica through `anx_model_use_execute_view` and verifies the original sealed sources.
Successful execution commits one logical operation.
Reconfiguration does not rewrite the logical program digest.

Malformed counts, foreign owners, mismatched sources, stale epochs, and insufficient capacity reject the relevant operation.
Preflight rejection preserves logical progress and caller output.
The current source remains authoritative even when an older private copy remains resident.
Only the controller can create shapes, compile placements, change geometry, or destroy records.
The owner can inspect its shape and execute an issued plan.

## Native checks

The [regression](../../kernel/core/tools/research_day074.c) creates a two-operation logical graph using the same sealed model source.
The first placement materializes one replica page.
Increasing the shape to two slots leaves that single page resident and invalidates the earlier plan.
Changing copied plan fields cannot repair the private stale epoch.

A fresh placement on the second slot materializes another page and produces `AAAA` through verified CPU generation.
The controller then issues the next placement on that slot and shrinks the shape to one slot.
The removed replica releases its physical page.
The second stale placement fails while the first completed logical result remains readable.

| Observation | Result |
| --- | --- |
| Materialized replica pages | One, then two, then one |
| Live replica payload bytes | 72, then 144, then 72 |
| Logical source identifier and digest | Unchanged |
| Logical program digest | Unchanged |
| Completed outputs after fresh placement | `AAAA`, `AAAA` |

The fixture rejects a third replica slot because the current phase covers only two pages.
It also rejects resize against an old epoch and destruction while plans retain the shape.
Corrupting the original model bytes blocks a plan despite its intact cached copy.
A later phase resize invalidates another plan independently of the shape epoch.
Fresh compilation against both current epochs completes the graph through the active owner.
Foreign execution and active-Cell attempts to resize or compile are rejected.

## Limits

The mutable geometry is a set of CPU-readable cache replicas for the 72-byte toy model.
Replica slots do not represent actual GPU workers, processor groups, context-parallel degrees, or concurrent execution lanes.
The experiment adds no automatic regime prediction, cache popularity policy, topology discovery, or split-and-merge GPU implementation.

The phase capacity check covers configured replica pages within this shape.
It does not account for every allocation, canonical source, other subsystem pool, or execution buffer owned by the Cell.
Reported physical pages come from the private replica pools; metadata allocations are outside that count.
Existing model and logical records retain their separate cleanup requirements.

Shaped compilation is an explicit API choice.
Existing physical plans without a shape retain their previous behavior.
All shape state remains within the current boot.
The fixture establishes identity preservation and placement invalidation, not latency, throughput, or energy improvements.
