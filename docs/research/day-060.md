# Day 060: Move model state while preserving logical identity

The August 24 briefing treats model state as a resource with identity, validity conditions, and transfer costs.
It separates authoritative execution state from disposable derived representations, including caches and resident adapters.
At comparison baseline `5acf978`, Anunix has transfer policy checks and immutable memory views.
Its transfer sessions hash streamed bytes without transporting storage, while memory compaction moves records only inside one pool.

## Scope

The source is [Day 060 in the daily review](daily-review.md#day-060--2026-08-24).
The source message identifier is `a5ddd2ca-0545-4045-823d-931bd901212f`.
This step implements physical relocation between native memory pools owned by the same Cell.
The acceptance fixture carries an executable toy adapter image and its existing version key through that path.

## Implementation

The [resource-view API](../../kernel/include/anx/resource_view.h) adds a controller operation that moves one immutable record and every alias referencing it.
The [implementation](../../kernel/core/mem/resource_view.c) preserves the logical record identifier, alias identifiers, owner, byte count, and payload digest.
Both pools must have the same owner.
An active Cell cannot start relocation, including the owner.

Before copying, the operation checks destination capacity, free record slots, free alias slots, and the caller's physical-page allowance.
It validates the source digest before allocating destination pages.
The copy crosses physical page boundaries without exposing raw mappings to consumers.
The destination digest must match before the registry publishes its new mappings.

Readers, alias changes, and relocation share the registry lock.
An allocation or verification failure preserves both pool inventories, every alias, and caller output.
The rollback clears copied bytes and releases newly allocated pages.
After success, the operation zeros the former source bytes; source compaction can then reclaim unused pages.
The result reports source and destination pool identifiers, bytes moved, and pages added.

| Condition | Result |
| --- | --- |
| Different owner | `ANX_EPERM` |
| Active Cell requests relocation | `ANX_EPERM` |
| Same source and destination | `ANX_EBUSY` |
| Missing handle or destination | `ANX_ENOENT` |
| Full record or alias table | `ANX_EFULL` |
| Insufficient capacity or page allowance | `ANX_ENOMEM` |
| Source or copied payload fails verification | `ANX_EIO` |
| Malformed arguments | `ANX_EINVAL` |

## Native checks

The [regression](../../kernel/core/tools/research_day060.c) inserts a 3464-byte adapter materialization after a 1000-byte source prefix.
The destination starts with a 3000-byte prefix.
The transfer therefore crosses page boundaries and allocates one destination page.
Both preexisting aliases retain their logical identity and return identical bytes.

The fixture verifies the stored adapter image against its generation key and executes the restored image through the native CPU backend.
The output remains `AAAA`.
It then releases the source prefix, reclaims two source pages, destroys the source pool, and executes through the surviving handle again.

Failure checks cover foreign ownership, exhausted alias space, limited capacity, zero page allowance, malformed bounds, source corruption, and corruption after copying.
They verify unchanged inventories, caller output, and allocator free-page counts.
The destination corruption hook is included only in research and host-test builds.

Publishing another adapter generation invalidates the transferred derivation key.
Rolling back to the original image does not revive that old generation.
Regeneration creates a new immutable record with a fresh key; the original record retains its bytes and identity.
An actual owner Cell rejects the stale materialization and executes the fresh one.
A foreign Cell cannot read, inspect, clone, release, or relocate the owner's handles.

## Limits

This is a synchronous local-memory transfer with a 4096-byte record limit and at most 32 pages per pool.
The controller supplies the page allowance; no bandwidth estimator or automatic placement policy selects it.
Holding the registry lock across allocation and copying bounds the operation but does not establish latency guarantees.
The copy does not migrate a running inference request or install state in another backend.

Resource views carry immutable bytes without interpreting their semantic schema.
Consumers must validate derivation keys before use, as the fixture does through the existing adapter API.
The operation does not grant access to a new owner or create durable provenance records.
The copied cache key uses the existing boot-local representation.

The tested adapter is the native toy CPU model's bounded delta image.
No GPU weights, KV cache, network transport, compression, or persistent checkpoint is implemented here.
This step does not reproduce the briefing's throughput, transfer-bandwidth, or model-quality claims.
