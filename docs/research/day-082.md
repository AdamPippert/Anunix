# Day 082: Hand a shared entitlement between continuation members

The September 15 briefing places resource entitlement on a cooperating continuation instead of granting independent capacity to each participating process.
The source message is `4fbd6461-2755-46a8-b94e-832520d9f3b2` in the [research conversation](https://chatgpt.com/c/6a3eabf4-cb88-83ea-942e-a601dd12b392).
Its broader design combines continuation groups, authority leases, constrained policy rules, and repartitionable resources.
The Anunix experiment implements one execution holder and one shared scratch reservation across an explicit group of Cells.

## Comparison

| Area | Existing Anunix | Day 082 change |
| --- | --- | --- |
| Scheduling authority | Scheduler domains constrain Cell ancestry, queues, and priority | A continuation group admits only its current execution holder |
| Resource accounting | Phase leases reserve capacity for individual owners | One group lease accounts for shared scratch pages across its members |
| Handoff | Separate Cells retain separate execution identities | The controller transfers group execution rights without replacing the lease or pages |
| Revocation | Existing domains and fences deny later work | Group revocation also releases its physical scratch pages and reserved capacity |

The [Day 061 scheduler domain](day-061.md) remains an independent admission boundary.
The [Day 067 continuation journal](day-067.md) preserves logical operation identity across worker replacement.
The new [continuation-group API](../../kernel/include/anx/continuation_group.h) supplies a separate, explicitly enrolled scheduling and memory experiment.
It does not replace the existing journal or imply that every continuation automatically belongs to a group.

## Implementation

The [group registry](../../kernel/core/sched/continuation_group.c) holds at most 16 groups.
The controller enrolls one through four direct children of a root owner.
Every participant must be new and quiescent, and a Cell cannot participate in two groups.
The registry retains the Cells and captures their admitted identity records.
The first listed member initially holds execution rights.

Each group allocates one through four physical pages of 4,096 bytes each.
A single L0 lease reserves and accounts for exactly those bytes.
The group records one execution slot on the existing bootstrap CPU.
That slot gates membership; it does not reserve a dedicated physical core or guarantee a fraction of CPU time.

Only the controller can hand execution rights to another member.
Handoff requires the current group epoch, quiescent participants, and a target that has not started.
The kernel rechecks the root, target ancestry, scope, contract, scheduler domain, identity, and run fence.
It also checks the existing lease's identity, reservation, usage, tier, accelerator fields, and optional expiry.
Successful handoff increments the epoch and changes the holder.
The lease, page allocation, and reserved byte count remain unchanged.

The current holder or controller can copy bytes through the group's bounded read and write APIs.
Both APIs require the current epoch and current holder authority.
Copies can cross page boundaries; the API exposes no raw page mapping.
Stale epochs, invalid bounds, foreign callers, and revoked groups reject before copying bytes.
A completed holder cannot access the group again; the controller first transfers rights to another eligible member.

The [runtime](../../kernel/core/exec/runtime.c) checks group admission before starting an enrolled Cell.
A waiting member returns a busy result while retaining its created state, so a later valid handoff can admit it.
The runtime, cognitive limit, [scheduler queues](../../kernel/core/sched/scheduler.c), and [external dispatch paths](../../kernel/core/exec/external.c) also check the current holder.
Cells outside an explicit group retain their existing behavior.

Controller revocation requires quiescent participants and the current epoch.
It revokes the lease, clears and frees the scratch pages, increments the epoch, and denies further execution and memory access.
A queued member must pass the group check again when dequeued.
Controller destruction releases the retained Cell references and removes the group.

## Native checks

The [fixture](../../kernel/core/tools/research_day082.c) enrolls three child Cells with one 8,192-byte lease and two physical pages.
It verifies the lease's reserved and used bytes against the available-capacity ledger.
A copied public view cannot change the holder or enlarge its reservation.

The second member cannot run or enter the scheduler queue before handoff.
Stale epochs, foreign targets, and changed target ancestry reject without changing the group view.
A foreign active Cell cannot inspect or read the group.
Active members cannot create, destroy, revoke, or hand off a group.

The first member writes eight bytes across a physical page boundary.
After handoff, the second member reads those bytes and replaces them with the next step's result.
The reservation remains 8,192 bytes, the physical allocation remains two pages, and the lease identifier stays fixed.
A held run fence prevents the next handoff.
After release, the third member receives the same scratch contents.

The controller queues the third member and then revokes the group.
The allocator's free-page count rises by two, and available lease capacity returns to its original value.
The queued member cannot dequeue or execute, and no third callback runs.
Later handoff and memory writes also reject.

## Limits

The experiment uses the kernel's synchronous bootstrap-CPU runtime and controller-mediated handoffs between quiescent Cells.
It does not implement Grouper's unprivileged core-transfer fast path, concurrent process isolation, or multicore resource allocation.
The scratch reservation covers only the group's private pages.
Ordinary Cell allocations, individual phases, GPU memory, model caches, and other resource APIs retain their existing accounting.

Membership is explicit and does not automatically enroll descendants or every Cell belonging to the root's task.
The group does not claim a system-wide CPU-time or memory quota for that task.
Its shared bytes are volatile and have no transaction journal or reboot recovery.
No trajectory-latency improvement, resource-second reduction, fairness result, GPU repartitioning, or model-scheduling speedup is claimed.
The briefing's broader authority compiler and typestate analyzer remain outside this bounded experiment.
