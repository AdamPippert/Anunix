# Day 054: Publish model adaptations with their cache identity

The August 18 briefing treats model adaptation as a staged version transition.
Derived state must identify the model version that produced it, and failed verification must leave the old serving image authoritative.
Anunix has model namespaces and explicit object staging, but the comparison baseline, `7a45ecf`, lacks a versioned adapter publication path in its working inference backend.

## Scope

The source is [Day 054 in the daily review](daily-review.md#day-054--2026-08-18).
The source message identifier is `5cba8a41-798c-4f31-b00b-12653231ce94`.
This step adds versioned adapters to Anxml's existing CPU toy model.
It exercises actual token generation across publication and rollback, without implementing LoRA training or GPU inference.

## Implementation

The [adapter manager](../../kernel/core/anxml/adapter.c) maintains up to 16 private adapter records.
Each record retains its owning Cell, current image, optional prior image, and at most one staged candidate.
An image contains one through 16 ASCII bigram adjustments, with each boost bounded from one through 4,096.
The format rejects duplicate pairs, invalid characters, malformed counts, and nonzero unused entries.

Only controllers can create, stage, verify, publish, abort, roll back, or destroy adapters.
The owner and controller can inspect the serving version and generate tokens.
Staging copies the candidate into private storage and binds it to the current generation.
Caller changes to the supplied image cannot alter the staged copy.
Pending candidates prevent destruction and rollback until they are published or aborted.

Verification runs one through four exact-output trials against the private candidate using the actual CPU inference routine.
Each trial uses greedy sampling, at most 128 generated tokens, and a bounded prompt.
A failed trial clears the candidate's verified state and prevents publication.
Verification checks these caller-selected examples; it does not establish general model quality.

Publication requires the matching candidate token, unchanged base generation, and successful private verification state.
Under one lock, the manager retains the old image, installs the candidate, and changes both the serving generation and image digest.
A fresh generation accompanies rollback even when the restored image has identical bytes to an earlier version.
Identifiers and generations never repeat within the current boot.

The [Anxml backend](../../kernel/core/anxml/anxml.c) applies each image's bounded adjustments while generating tokens.
The adapter entry point snapshots the serving image and generation together before inference.
The response's cache key carries that snapshot, its digest, and a hash of the prompt, token bound, and sampling seed.
Cache checks reject a different adapter, generation, image digest, or request identity.
Publication for one adapter leaves another adapter's cache identity unchanged.

Generation and initialization now serialize access to the toy model's shared bigram table.
The default generation path retains its existing behavior and rejects an out-of-bounds prompt length.
The versioned entry point accepts an explicit adapter identifier, an empty model-name field, and a token bound from one through 128.

## Native checks

The [regression](../../kernel/core/tools/research_day054.c) generates `AAAA` from an initial adapter and stages a candidate that generates `BBBB`.
The old adapter continues serving before verification, after a failed trial, and after successful verification before publication.
Publication changes the output to `BBBB`, rejects the old generation, and invalidates the old cache key.
Rollback restores `AAAA` under a fresh generation while keeping earlier cache keys invalid.

The regression also checks incorrect candidate tokens, stale generations, caller-image mutation, abort, pending-state conflicts, malformed input, and unchanged output after rejection.
A second adapter keeps its valid cache key throughout the first adapter's update.
Changes to the prompt or sampling seed invalidate a key.
An actual foreign Cell cannot inspect or execute the adapter; its owner can generate tokens but cannot publish or destroy it.
A completed owner prevents new staging while allowing controller cleanup.

## Limits

The adapter format adjusts a deterministic toy bigram model; it is not a LoRA format or a trainable foundation-model adapter.
The controller supplies initial images and selects verification examples.
Those finite examples provide no statistical quality guarantee, held-out benchmark, or automatic regression threshold.

The cache key validates metadata only; the implementation stores no KV tensors and performs no cache warming or physical cache reclamation.
Generation snapshots may finish after publication using their old coherent image and old key.
Consumers must validate keys before reuse and handle a stale-generation response when starting work.
Default workflow dispatch does not select versioned adapters automatically.

All images, lineage, verification state, and identifiers are local to the current boot.
The manager retains one rollback image and provides no crash recovery, durable audit record, or cross-boot cache compatibility.
Synchronous verification holds the adapter lock, and generation holds the inference lock with interrupts disabled.
Contention, interrupt latency, model quality, foreground latency, and training throughput remain unmeasured.
