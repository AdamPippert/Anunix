# Day 021: Trial typed routing policies with rollback

The July 16 briefing places validated policy changes between slow model reasoning and deterministic resource execution.
The comparison baseline, `b3ed9c7`, validates simulated routing weights but hardcodes the live planner's weights.
The baseline has no live policy trial or rollback controller.

## Scope

The source is [Day 021 in the daily review](daily-review.md#day-021--2026-07-16).
The source message identifier is `4d0e3645-bcdc-41c0-bb55-a3e4cd28e04e`.
This step exposes the eight existing scoring weights through a typed trial API.
The controller changes scores; resource leases and execution permissions retain their existing enforcement paths.

## Implementation

The [controller](../../kernel/core/route/tuning.c) accepts schema version 1, an expected generation, and a complete weight policy.
Bonuses accept zero through 1000 score points; penalties accept minus 1000 through zero score points.
CPU and GPU cost divisors accept integers from one through 1000.
The defaults preserve the baseline weights: locality 20, local-first 30, divisors 5 and 10, degradation minus 25, private-data 10, topology 25 and minus 15.

Only trusted kernel control code outside an active cell can begin or finish a trial.
Malformed actions return `ANX_EINVAL` before policy mutation.
A stale expected generation or overlapping trial returns `ANX_EBUSY` without changing the output identifier.
The controller reserves generation space for trial completion and rejects counter exhaustion with `ANX_EFULL`.

Beginning a trial saves the prior weights and activates the proposed weights under a lock.
The returned generation identifies the active trial.
A rejected trial restores the prior weights; an accepted trial retains the proposed weights.
Both outcomes advance the generation and close the trial.
Old identifiers cannot finish a later trial.

The general planner and session planner each copy one policy for the entire routing decision.
The Resource Twin's incumbent accessor returns the current live weights; simulation itself still cannot activate a policy.
JEPA's existing score adjustment remains separate from those deterministic weights.

The general planner now tracks whether a feasible best candidate exists, without treating minus one as the lowest valid score.
The ranking check covers negative scores and compares both candidate orderings.
Live scoring rejects CPU weights, GPU weights, and quality scores above 100 points before arithmetic.

The [native regression](../../kernel/core/tools/research_day021.c) rejects malformed proposals, overlapping trials, stale generations, and mutation requests from an active cell.
The regression observes changed session placement during a valid trial and restores the previous placement after rejection.
It also accepts a valid trial, checks negative scores, and restores the original policy before completion.
Session feasibility checks still reject an unauthorized remote model despite the active trial weights.

## Limits

The controller accepts a trusted caller's trial verdict; the controller does not collect benchmarks or authenticate performance evidence.
A generation identifier prevents stale updates and does not authenticate a controller identity.
Trials have no automatic expiration or rollback timer.
The controller must close each active trial.

The policy is volatile and returns to its defaults after reboot.

The API adds no model proposal service, Linux control adapter, transition-cost estimator, scheduling cadence, or automatic tuning loop.
The change does not migrate an existing session or override its eligible affinity.
The fixtures use fresh session requests to measure placement changes.
Performance overhead and the briefing's reported improvements remain unmeasured.
