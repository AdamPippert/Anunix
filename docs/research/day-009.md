# Day 009: Authority at object access

The July 4 briefing argues that policy must govern the operation beneath a model-visible tool.
Anunix already evaluates object access policies, but the comparison baseline, `ca47725`, does not supply the executing cell's identity.
It also treats an object's creator as a matching requester, which lets an unrelated cell use an owner-specific permission.

## Scope

The source is [Day 009 in the daily review](daily-review.md#day-009--2026-07-04).
The source message identifier is `71a4dede-4ed0-409a-b882-c241fa4c4867`.
This step enforces payload access through the ordinary State Object API used by a dispatched handler.

## Implementation

The synchronous runtime records the active cell and restores the previous identity after nested execution.
Object opening evaluates policy against that identity.
Creator identity remains provenance and no longer supplies the caller's permission.
Calls outside a cell run have no specific cell identity.

A read/write handle must pass both checks.
A write-only handle cannot read payload bytes.
Invalid open modes are rejected.

The [native regression](../../kernel/core/tools/research_day009.c) defines two rules.
An owner-specific grant precedes a wildcard denial.
An unrelated cell attempts a write through its external handler; the object must retain its payload and version.
The owner then invokes another unrelated cell and successfully writes after that nested denial returns.
An anonymous caller remains denied after the owner finishes.
Further cases check read/write opening and reading through a write-only handle.

Two existing host tests relied on the old handle behavior.
The [initial host run](evidence/day-009/host-integration-failure.log) records those failures while the new runtime regression passes.
The staged mutation fixture now requests a read/write handle for its readback.
The access-policy fixture checks that a denied read blocks read/write opening while still permitting a write-only handle.

## Limits

The active identity belongs to the current synchronous runtime; it is not a per-thread execution context.
Concurrent cell execution will require context storage at that scheduling boundary.
The policy retains its existing first-match rules and permissive behavior when no rule matches.
This change covers payload handles; it does not claim enforcement for every metadata, deletion, sealing, transport, or raw kernel operation.
Open handles do not yet revalidate policy or caller identity on every use.
Trusted kernel callers can access object structures directly.
