# Day 053: Admit only enforceable execution contracts

The August 17 briefing distinguishes semantic consistency, exact model replay, and transactional effects.
Each guarantee requires its own enforcement mechanism and resource costs.
Anunix already exposes consistency declarations and explicit object staging, but the comparison baseline, `07bc005`, does not enforce those declarations during execution.

## Scope

The source is [Day 053 in the daily review](daily-review.md#day-053--2026-08-17).
The source message identifier is `c32c6f5c-3fd5-4876-84a4-47e7958510a4`.
This step separates a requested guarantee from a supported execution mode.
It also verifies the narrower staging operations already implemented for individual State Objects.

## Implementation

The [contract API](../../kernel/include/anx/cell.h) adds an explicit token-stable consistency request.
The setter validates all consistency and effect values without changing the contract on malformed input.
Only a controller can configure a Cell that remains in its created state.
Executing Cells cannot rewrite their own contracts or configure another Cell through this setter.

The [runtime](../../kernel/core/exec/runtime.c) checks support during admission, before planning or invoking any external handler.
Current support is limited to best-effort consistency with direct effects.
Semantic, transactional, token-stable, and automatically staged execution return `ANX_ENOTSUP`.
Unknown enum values return `ANX_EINVAL`, including values written directly into public fields by a controller.
The failure trace identifies the execution-contract admission gate.

The [external-call boundary](../../kernel/core/exec/external.c) repeats the support check before invoking a handler for an executing Cell.
The runtime also compares the final declaration with its entry snapshot before validation and completion.
A changed declaration fails the run without claiming that an earlier effect was rolled back.
Default best-effort execution retains its existing behavior.

The [staging API](../../kernel/core/state/stage.c) remains an explicit, single-object mechanism.
It keeps a proposed payload separate from live readers until an authorized commit succeeds.
A changed base version prevents publication.
Abort discards the proposal while retaining an abort event in object provenance.
These operations do not imply a transaction across an entire Cell, filesystem, or external service.

## Native checks

The [regression](../../kernel/core/tools/research_day053.c) first requests transactional execution with staged effects from an external-call Cell.
The candidate rejects that request before the handler runs and preserves a finalized denial trace.
A matrix exercises all four consistency classes with both effect modes.
Only the best-effort/direct combination reaches the handler.

The regression also covers malformed setter input, malformed public fields, active-Cell setter rejection, and reentrant invocation after deliberate contract drift.
A handler that leaves its declaration changed cannot complete successfully.
The host contract test now expects rejection where it previously accepted an unenforced transactional claim.

A separate object fixture proves that a staged proposal remains invisible to a live reader.
A simulated competing base revision causes commit to fail without publishing the proposal.

Abort records its owner in provenance, and a fresh stage subsequently commits the accepted bytes.

## Limits

This change rejects unsupported guarantees; it does not add deterministic inference, semantic postcondition validation, or automatic transactional workspaces.
The existing runtime validation and output-persistence stubs remain unavailable as strong consistency guarantees.
Explicit object staging provides no multi-object atomicity, durable crash recovery, or rollback of arbitrary network effects.
Abort provenance records the attempt, without retaining the complete discarded payload.

Public kernel structures remain trusted metadata.
Entry and completion checks cannot detect every transient modification by arbitrary trusted code.
Controller-only external invocations retain their existing administrative behavior outside an executing Cell.
The source's GPU determinism, filesystem integrations, and task-level performance comparisons remain untested.
