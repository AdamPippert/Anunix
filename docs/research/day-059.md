# Day 059: Preserve logical inputs across engine rebinding

The August 23 briefing separates logical identity from the physical representation that executes work.
It treats current state, superseded history, and backend selection as distinct concerns.
At comparison baseline `cd51346`, Anunix can retain engine affinity, but its caller-owned session does not freeze a task's model and input versions.
This step adds a private model binding with fresh semantic and readiness checks before each placement decision.

## Scope

The source is [Day 059 in the daily review](daily-review.md#day-059--2026-08-23).
The source message identifier is `0808d44d-d49e-4e35-a05c-d1ddb54743e5`.
The implemented binding is a planning record for model engines.
It does not dispatch inference, transfer execution state, or prove semantic equivalence between backend implementations.

## Implementation

The [binding registry](../../kernel/core/route/binding.c) holds at most 32 private records.
Controller code supplies a Cell, a sealed model definition, and a compatible pool of at most eight registered model engines.
The specification also declares required capabilities and a positive context capacity in tokens.
The caller owns the compatibility claim; the registry captures each engine's model and authority metadata.

The registry captures the Cell's declared inputs, dependencies, intent, policies, and authority identifiers.
Only read inputs are supported; a write input returns `ANX_ENOTSUP`.
A required missing input returns `ANX_ENOENT`.
Each model or input object must contain 1–65536 bytes.
The registry records its version, sensitivity, schema, type, and payload digest.

The binding retains the Cell's reference while keeping input snapshots as evidence.
The model and Cell identities remain fixed across engine selection.
Each successful selection advances the binding epoch, including a repeated selection of the same engine.
A stale epoch returns `ANX_EBUSY`.
A failed selection preserves both the private view and caller output.

Before selection, the registry rechecks delegated scope, execution contracts, identity admission, and completed dependencies.
Changed declarations or object snapshots return `ANX_EBUSY`.
An object access denial returns `ANX_EPERM`.
A deleted model or input returns `ANX_ENOENT`.
A pending dependency returns `ANX_EBUSY`; a failed dependency returns its existing failure result.

The registry also checks each backend's current readiness:

| Check | Required condition |
| --- | --- |
| Engine descriptor | Captured model and authority metadata still match. |
| Engine state | The engine is available or degraded. |
| Model server | The server serves requests and has a free queue slot. |
| Resource lease | The engine holds its registered, unrevoked, unexpired lease. |
| Memory reservation | The reservation covers the declared model footprint. |
| Context capacity | The known capacity covers the requested token count. |
| Private inputs | The engine declares private-data support. |
| Routing policy | Current locality, network, capability, and scoring checks pass. |

The existing [session planner](../../kernel/core/route/session.c) retains affinity among eligible engines or selects a scored fallback.
No ready backend returns `ANX_ENODEV`; a pool that violates routing policy returns `ANX_EPERM`.
An owner or controller can inspect and select a binding.
Only the controller can create or destroy one; a foreign Cell receives `ANX_EPERM`.
A terminal owner cannot select a backend, but the controller can inspect and remove its record.

## Native checks

The [regression](../../kernel/core/tools/research_day059.c) creates a model definition, mutable state input, dependent task, and three model engines.
It proves that a pending dependency and missing model servers prevent placement.
The fixture then starts native model servers with 4096-byte logical weight reservations.

The task moves between two local engines as the fixture changes availability, queue capacity, lease validity, context capacity, and model metadata.
The Cell identifier, model identifier, and model version remain unchanged.
The selected engine changes while the epoch advances.
A higher-scored remote engine cannot override the task's local-only policy.

An input update invalidates the old binding.
Writing the original bytes back creates another version and cannot revive that binding.
A fresh binding accepts the new version while retaining the same Cell and model identities.
Other checks cover in-place corruption, revoked read access, failed dependencies, malformed specifications, and mutation of the caller's original pool.

An actual owner Cell selects its binding during execution.
A foreign Cell cannot inspect, select, check, create, or destroy that binding.
After the owner completes, selection fails, and controller cleanup releases its retained reference.

## Limits

The captured model definition is caller-provided data; the registry does not lower or execute a canonical model graph.
Backend compatibility remains a controller assertion, rather than a tested equivalence guarantee.
The native model servers still use their existing inference stub.
The fixture tests placement and lifecycle behavior without claiming model output parity or migrated execution state.

Snapshots and checks provide current planning evidence, not an atomic transaction with later inference dispatch.
The engine and server registries retain their existing synchronous lifetime assumptions.
The declaration digest uses boot-local representations and is not a portable or signed wire format.
Objects can change after selection; the consumer must recheck before use.

The binding does not create a durable event log or infer supersession relationships.
It rejects changed input evidence until the controller creates a fresh binding.
This step does not reproduce the briefing's memory accuracy, compiler speedups, hardware simulation, or throughput claims.
