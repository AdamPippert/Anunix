# Day 072: Check evidence independence before a staged change commits

The September 5 briefing distinguishes reviewer count from independence of the evidence supporting those reviewers.
At comparison baseline `627ecc0`, Anunix checks staged-write authority and object versions without measuring shared evidence dependencies.
This step attaches a bounded evidence quorum to an existing staged change.
The ordinary commit path rejects an enrolled change without enough current approvals and modeled evidence separation.

## Scope

The source is [Day 072 in the daily review](daily-review.md#day-072--2026-09-05).
The source message identifier is `1ddbc849-f8fc-464b-a905-d204e865fa77`.
The briefing describes epistemic fault domains, typed future intentions, and migration through application state graphs.
This experiment implements the evidence admission boundary.
It adds neither an intention service nor heterogeneous migration.

The briefing's structural cut counts the smallest modeled root-fault set that covers a decisive reviewer coalition.
Several reviewers can share one root and therefore provide a cut of one.
The briefing describes mechanism simulations, with no released measurements from real model endpoints.
The native fixture tests the dependency calculation and enforcement; it makes no model-quality claim.

## Comparison

Existing staged mutations isolate proposed bytes and check the writer before publication.
Object provenance records parent identifiers, while identity and scope checks govern Cells.
Neither mechanism checks whether a reviewer quorum depends on the same upstream object.

The [new API](../../kernel/include/anx/epistemic.h) binds approved reviewers to a specific staged change.
The [implementation](../../kernel/core/state/epistemic.c) captures sealed evidence and its parent graph.
The [stage hooks](../../kernel/core/state/stage.c) enforce that record during ordinary commit and resolve it during commit or cancellation.
Unenrolled stages retain their existing behavior.

## Implementation

The controller creates an immutable specification with one to eight distinct reviewers, a vote threshold, and a minimum structural cut.
The owner cannot also serve as a reviewer.
The record pins the owner and reviewer Cells and captures their identity records.
It binds the target identifier, base version, sensitivity, and digest of the proposed bytes.
The registry holds at most 16 records.

Only a listed active reviewer can cast its single approval or rejection.
Each vote names sealed byte or structured evidence with at most 4096 payload bytes per object.
The graph admits at most 32 objects, eight parents per object, and eight roots.
Traversal rejects cycles, the staged target, and paths beyond the bounded depth.
Failed traversal removes newly captured nodes without registering a vote.

A root is a captured object without parents.
The runtime follows actual parent identifiers and hashes actual payload bytes while holding each object's lock.
It checks read access as the reviewing Cell and rejects evidence above the target's sensitivity.
Each approving vote retains the set of captured ancestors and modeled roots it uses.
Distinct object roots represent the configured fault model; they do not prove real-world independence.

Assessment rechecks each approving reviewer's identity and scope.
It also rechecks every captured ancestor's payload, version, parents, sensitivity, and current read access.
An invalid dependency excludes that reviewer's approval.
The runtime enumerates root-fault sets and finds the smallest set covering the configured number of valid approvals.
Readiness needs both the approval threshold and the minimum structural cut.

The normal commit path checks the frozen proposed bytes and current owner identity before assessing the evidence.
Insufficient current evidence returns `ANX_EAUDIT` without publishing the staged bytes.
A changed staged payload returns `ANX_EBUSY`.
Success records `COMMITTED`; cancellation records `ABORTED`.
The controller can destroy a resolved record and release its Cell references.

Only the owner or controller can inspect the assessment.
Copied public fields cannot alter the private graph or authorize publication.
The public `ready` field describes the evidence quorum; the commit path still checks proposal and write authority separately.
Terminal records preserve their last assessment for inspection within the current boot.

## Native checks

The [regression](../../kernel/core/tools/research_day072.c) uses three actual reviewer Cells and a two-of-three threshold.
Every case also needs a structural cut of two.
The fixture compares three graphs before and after corrupting one root's actual payload.

| Evidence graph | Healthy approvals | Healthy cut | Approvals after one root fault | Commit after fault |
| --- | --- | --- | --- | --- |
| All reviewers share one root | 3 | 1 | 0 | Rejected |
| Two reviewers share a root; one uses another | 3 | 1 | 1 | Rejected |
| Each reviewer uses a separate root | 3 | 2 | 2 | Accepted |

The mixed graph proves that counting distinct roots alone cannot establish the required cut.
The separate graph commits the exact proposed `new!` bytes through the active owner after one approval becomes invalid.
Rejected cases preserve the old bytes, object version, and open stage until explicit cancellation.

Further checks reject duplicate votes, controller votes, foreign callers, cyclic evidence, and the staged target as evidence.
Changes to copied public fields cannot bypass the checks.
Changing the proposed bytes blocks commit until the original bytes return.
Changing a second ancestor's parent, version, or read policy also blocks commit.
The fixture restores each injected fault and cleans up its records and Cells.

## Limits

The controller enrolls an individual stage; this is not a permanent policy on all future writes to the target.
Existing authority can cancel that stage and create another unenrolled stage.
Persistent mandatory review policy would need another admission boundary.

The graph models explicit object ancestry only.
Separate roots can still share a hidden database, provider, model lineage, or network dependency.
The structural cut therefore measures the captured fault model, not the probability of a safe real-world decision.
The fixture includes no model inference, external reviewer service, production decision, or cost measurement.

Records and votes remain in memory within one boot.
This step adds no durable quorum journal, external signature verification, or distributed atomic commit.
Existing object deletion removes objects from lookup without necessarily releasing every underlying allocation.
The experiment does not establish memory reclamation or concurrent multiprocessor guarantees.
