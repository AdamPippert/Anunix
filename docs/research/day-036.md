# Day 036: Keep delegated reservations within the parent grant

The July 31 briefing separates global admission, delegated scheduling authority, local policy, and state readiness.
The comparison baseline, `72ab01b`, accounts for every engine lease against global capacity.
The baseline has no parent reservation or delegated capacity boundary.

## Scope

The source is [Day 036 in the daily review](daily-review.md#day-036--2026-07-31).
The source message identifier is `7037ad65-bc52-48dc-a3c7-faa6f20e6f40`.
This step adds nested reservations to the existing lease ledger.
The baseline test branch adds a delegation adapter over the flat allocator to expose the missing parent bound.
The change does not introduce a CPU scheduler or predict admission wait times.

## Implementation

The [lease ledger](../../kernel/core/route/lease.c) permits a child reservation only within its registered, active parent.
Children inherit the memory tier and accelerator type.
The gate subtracts the parent's recorded memory use and its active direct children before granting another child.
It also subtracts those children's accelerator percentages from the parent grant.
A request beyond either remaining limit returns `ANX_ENOMEM` without allocating a record.

Only active roots reduce global availability.
Children subdivide an existing reservation and do not consume the same global capacity again.
The hierarchy permits eight delegation levels below a root.
An expired record is not inferred from elapsed time; the existing expiry field still has no automatic enforcement.

The revocation operation checks the complete subtree before changing any record.
Any recorded memory use returns `ANX_EBUSY` and leaves the subtree unchanged.
Otherwise, the operation marks the root and descendants revoked under the ledger lock.
Revoked records cannot grant children and no longer appear in engine lease lookup.

Revoking a child returns its delegated portion to the parent.
Revoking a root returns its reservation to the global ledger.
Revocation retains records for explicit cleanup, so callers do not receive dangling descendant pointers from that operation.
Release requires zero recorded use and no remaining child records, including revoked children.
A caller must release descendants before their parent.

Root and child grants reject empty engine identifiers and duplicate identifiers while an earlier record remains registered.
Accelerator percentages range from 0 through 100; `ANX_ACCEL_NONE` requires zero.
An unregistered parent returns `ANX_ENOENT`, while a revoked parent or exhausted hierarchy depth returns `ANX_EPERM`.

The [native regression](../../kernel/core/tools/research_day036.c) rejects a child above its parent's memory or accelerator grant.
The fixture checks sibling accounting, nested grants, unchanged global reservation totals, and leaf-first release.
A recorded byte of use blocks subtree revocation without partial changes.
Child revocation permits replacement within the parent; root revocation restores global ledger capacity.
The fixture also checks unregistered records and the eight-level hierarchy limit.

## Limits

The default ledger capacity remains 16 GiB per memory tier and 100 percent per accelerator.
Those defaults do not measure the Jekyll guest's physical memory or prove available accelerator capacity.
The fields track reservations and recorded use, without page allocation, hardware enforcement, or automatic usage instrumentation.

The controller must stop physical users before revocation; a zero recorded count alone does not prove that hardware execution has stopped.
Revocation does not cancel a model server, preempt a task, or transfer CPU ownership.
The change adds no cell-to-domain authority binding, ready-state ticket, exact wait quote, or remote admission protocol.

The record fields remain mutable native structures, and existing lookup returns an uncounted pointer.
The ledger lock serializes these API operations but does not isolate arbitrary kernel writes or solve concurrent pointer lifetime management.
The tests establish reservation arithmetic and lifecycle behavior without a federated workload performance claim.
