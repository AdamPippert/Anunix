# Day 008: Preserved execution lineage

The July 3 briefing separates agent identity, task branches, tool calls, and transport primitives.
Its audit model requires those relationships to remain inspectable after execution.
Anunix cells already carry parent identifiers, and Day 006 enforces delegated bounds.
The comparison baseline, `7985529`, leaves parent and plan fields empty in materialized traces and keeps those objects writable.

## Scope

The source is [Day 008 in the daily review](daily-review.md#day-008--2026-07-03).
The source message identifier is `7ae8ff25-29ce-435f-8a3c-f20a4e699dcc`.
This step preserves the identity relationships around a child tool call.

## Implementation

The runtime copies the parent identifier into the trace before admission.
It records the plan identifier when the plan is finalized.
An admission denial therefore retains parent lineage with no plan identifier.
A completed call retains its parent, cell, and plan identifiers.

Trace materialization assigns the `anx:schema/cell-trace/v1` schema and seals the object before returning its identifier.
A failed materialization leaves the trace eligible for a later finalization attempt.
The [native regression](../../kernel/core/tools/research_day008.c) runs denied and authorized child calls, destroys their cell records, and reads the sealed traces.
It checks creator identity, parent lineage, plan identity, schema, and rejection of a write handle.

## Limits

Sealing prevents payload changes through the State Object API; it is not a digital signature.
The record remains in the current object store and this test does not establish persistence across guest reboot.
The trace contains native C structures, so its schema is tied to this implementation's layout.
Trusted kernel code can still access internal structures directly.
Materialization errors are still best effort in the runtime; enforcing audit availability before effects remains separate work.
