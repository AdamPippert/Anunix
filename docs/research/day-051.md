# Day 051: Resize resources without replacing the task

The August 15 briefing separates identity, protection, execution, scaling, memory, and commit units.
Anunix already separates Cells, execution engines, and resource leases.
The comparison baseline, `b04649e`, requires closing a phase before changing its reservation.

## Scope

The source is [Day 051 in the daily review](daily-review.md#day-051--2026-08-15).
The source message identifier is `99f0ff6a-48dd-4690-8156-018b950d3c27`.
This step adds controller-directed resizing within an active phase.
The experiment tests resource accounting and identity preservation, without implementing operator scheduling or GPU execution.

## Implementation

The [lease manager](../../kernel/core/route/lease.c) accepts new memory and accelerator reservations for an existing lease.
Resizing preserves its engine identifier, pointer, tier, accelerator type, ancestry, creation time, and expiration.
A request must fit the remaining capacity after other root reservations, or its parent's remaining capacity after siblings and recorded usage.
A shrink must still cover recorded memory usage and every active child's reservation.
Checks use bounded subtraction before changing either reservation.

The [phase broker](../../kernel/core/route/phase.c) applies its private contract ceilings before calling the lease manager.
A successful resize retains the owner, phase kind, and lease identifier while issuing a fresh phase epoch.
Old resize and finish requests then fail with `ANX_EBUSY`.
Failure leaves the allocation, epoch, and output view unchanged.
The broker rejects terminal owners and detects direct controller changes that disagree with its cached lease view.

Both resize APIs reject calls from an executing Cell.
The controller remains responsible for choosing allocations and coordinating actual resource users.
The phase wrapper enforces phase ceilings; the lower-level lease API only enforces ledger capacity and ancestry.
Trusted controllers must use the phase wrapper for phase-owned leases.

## Native checks

The [regression](../../kernel/core/tools/research_day051.c) expands a reservation from 1,024 to 2,048 bytes and from 10% to 20% accelerator capacity.
It checks unchanged task and lease identities, exact availability changes, and a fresh epoch.
Separate competing leases exhaust memory and accelerator capacity, causing growth to fail without partial changes.

Two child leases exercise parent accounting and sibling competition.
Recorded parent usage prevents unsafe shrinking.
After reducing a child reservation, the phase shrinks to its exact remaining minimum.
The test also covers contract ceilings, stale requests, revoked leases, malformed requests, direct-controller drift, and a terminal owner.
An actual foreign Cell cannot resize either the phase or its raw lease.
Cleanup restores the original memory and accelerator availability.

## Limits

Reservations describe logical budgets; resizing does not migrate memory, preempt an engine, or change physical accelerator scheduling.
Recorded memory usage must accurately represent active users before the controller requests a shrink.
Accelerator percentages have no separate usage counter, so the controller must coordinate any reduction with executing work.
The existing raw lease registry and trusted-controller concurrency assumptions remain in place.
Operator-level elasticity, certified caching, and source performance claims remain untested.
