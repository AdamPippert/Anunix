# Day 035: Preserve destination scope and transfer identity

The July 30 briefing models data movement with explicit destinations, ownership, consistency, and correctness obligations.
The comparison baseline, `6b5a9e2`, checks a raw destination prefix at transfer start and resume.
A rule for `anx://store` also accepts `anx://store-extra`, and a revoked rule does not prevent commit.

## Scope

The source is [Day 035 in the daily review](daily-review.md#day-035--2026-07-30).
The source message identifier is `6ee3d16a-44f6-4657-ae00-480794c4c9a6`.
This step tightens the native transfer session and its destination contract.
The transfer module records hashes and metadata; it does not transport bytes across devices.

## Implementation

The [transfer policy](../../kernel/core/state/xfer.c) validates bounded, canonical namespace URIs before matching destinations.
Source and destination strings have a maximum length of 127 bytes, plus the terminating byte.
Provenance tags have a maximum length of 63 bytes, plus the terminating byte.
Long inputs return `ANX_EINVAL` without truncation.

The supported URI form contains a scheme, `://`, an authority, and an optional path.
Schemes start with a letter and can contain letters, digits, plus signs, hyphens, and dots.
Authorities contain letters, digits, dots, hyphens, and underscores, with an optional numeric port from 1 through 65,535.
Path components contain letters, digits, dots, hyphens, underscores, and tildes.
The parser rejects empty interior components, dot segments, escapes, user information, queries, fragments, whitespace, and unsupported characters.

| Rule | Destination | Result |
| --- | --- | --- |
| `anx://store` | `anx://store/out` | Allowed |
| `anx://store` | `anx://store-extra/out` | Denied |
| `anx://store/allowed` | `anx://store/allowed/out` | Allowed |
| `anx://store/allowed` | `anx://store/allowed-more/out` | Denied |
| `anx://` | Any supported authority under `anx` | Explicitly allowed |

A match must end at a complete authority or path component.
An explicit scheme-only prefix retains the existing broad grant for that scheme.
A malformed active rule invalidates the whole policy before any rule can grant access.
An oversized rule count returns `ANX_EINVAL` before array access.
The policy supports eight rules.

Each write and commit rechecks the current destination policy; resume retains its existing recheck.
A denial changes the session to `ANX_XFER_ABORTED` before another chunk enters the digest or commit produces a valid result.
Every failed commit clears the result structure.
The write path also rejects a message length beyond the SHA-256 length field before the counter can overflow.

The [native regression](../../kernel/core/tools/research_day035.c) checks authority and path boundaries, malformed inputs, oversized fields, and malformed rules.
The fixture revokes policy before a write and before commit, then checks the aborted state and unchanged accepted byte count.
A resumed transfer hashes the same 14-byte payload as a direct SHA-256 calculation.
The successful result retains the exact destination and provenance tag.
The existing host cases retain the explicit scheme-wide grant.

## Limits

The URI grammar is a restricted native namespace contract, not a complete web URL parser.
The implementation performs no decoding, DNS lookup, redirect following, filesystem traversal, or backend canonicalization.
Transport backends must preserve these namespace meanings and apply their own authorization checks.

Policies and sessions remain caller-owned structures without private issuance records, signatures, or immutable intent binding.
Trusted kernel code can mutate them directly, and no shared lock makes concurrent policy changes atomic with every transfer operation.
The module produces a payload digest and metadata without proving actual remote delivery or ownership transfer.
The change adds no device movement graph, DMA backend, scheduler proof, latency measurement, or formal verification.
